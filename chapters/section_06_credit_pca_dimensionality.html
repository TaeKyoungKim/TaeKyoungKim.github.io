6부. 차원 축소 — 청구·상환 변수의 PCA

이 절에서 원문 대비 달라진 점: 원문(Chapter 06, 331~375쪽)은 차원 축소 이론(분산·공분산·고유값/고유벡터), PCA(iris 데이터 실습 포함), 그리고 신용카드 데이터셋을 이용한 PCA 실습(원문 351~355쪽에서 실제로 이 UCI 신용카드 데이터를 사용한 것을 PDF에서 직접 확인함)을 다루며, 이어서 LDA(Linear Discriminant Analysis)와 SVD·NMF(행렬 분해) 기법도 함께 다룬다. 이 절은 원문의 신용카드 PCA 실습을 그대로 계승하되, 2~4부에서 이미 사용한 credit_default(UCI Credit Card Default) 데이터의 청구액(BILL_AMT1~6)·상환액(PAY_AMT1~6) 12개 변수로 대상을 구체화했다. iris 데이터를 이용한 PCA 실습은 이 교재의 범위(금융 데이터)에 맞지 않아 다루지 않으며, LDA·SVD·NMF는 원문에 포함되어 있으나 지면상 이 절에서 다루지 않고 통합 단계의 원문 대응표에 누락으로 명시한다(1단계 설계에서 확정, 통합 검토 시 재확인).

1. 금융 상황과 해결할 질문

2~4부에서 확인했듯 BILL_AMT1~BILL_AMT6(최근 6개월 청구액)는 서로 매우 강하게 상관되어 있다 — 한 고객의 이번 달 청구액을 알면 지난달 청구액도 어느 정도 짐작할 수 있기 때문이다. 이렇게 서로 겹치는 정보를 담은 변수 12개를 그대로 모델에 넣는 대신, "핵심 정보만 압축한 몇 개의 새 변수"로 줄일 수 있다면 대시보드 시각화나 저장 공간, 계산 비용 면에서 유리하다. 이번 절의 질문은 다음과 같다.

서로 강하게 상관된 청구·상환 금액 12개 변수를, 정보를 얼마나 잃지 않으면서 몇 개의 새로운 변수로 압축할 수 있는가? 그리고 그렇게 압축한 변수로 원래의 예측 성능(4부에서 확인한 연체 예측)을 얼마나 유지할 수 있는가?

2. 학습목표와 선수지식

  1. 분산·공분산의 의미와, 주성분분석(PCA)이 "분산이 가장 큰 방향"을 어떻게 찾는지 손으로 계산할 수 있다.
  2. 설명 분산 비율(explained variance ratio)과 스크리 플롯을 읽고, 몇 개의 주성분을 남길지 판단할 수 있다.
  3. PCA도 표준화와 마찬가지로 학습 세트에만 fit해야 하는 전처리 단계임을 이해하고, 이를 지키지 않으면 어떤 문제(데이터 누수)가 생기는지 설명할 수 있다.

선수지식: 2부의 StandardScaler와 ColumnTransformer, 3~4부의 학습/테스트 분할 원칙.

3. 직관적 설명

12개의 서로 다른 각도에서 찍은 같은 건물의 사진이 있다고 생각해보자. 사진마다 조금씩 다르지만, 사실 "건물이 얼마나 큰가"라는 하나의 정보가 대부분의 차이를 만들어낸다. PCA는 이런 상황에서 "가장 많은 차이(분산)를 설명하는 방향"을 하나씩 찾아나간다 — 첫 번째로 가장 많은 정보를 담은 방향(제1주성분), 그 다음으로 (첫 번째와 무관하게) 가장 많은 정보를 담은 방향(제2주성분), 이런 식으로 이어진다. 12개의 청구·상환 변수도 마찬가지다 — "이 고객이 전반적으로 얼마나 많이 쓰고 얼마나 많이 갚는가"라는 몇 개의 큰 흐름이 12개 변수의 차이 대부분을 설명할 가능성이 높다.

4. 용어와 수식

공분산 행렬(Covariance Matrix): $p$개 변수 사이의 분산과 공분산을 담은 $p \times p$ 행렬. 변수를 평균 0으로 중심화($\tilde{x} = x - \bar{x}$)한 뒤 다음과 같이 계산한다.

$$\Sigma = \frac{1}{n-1} \tilde{X}^T \tilde{X}$$

고유값(eigenvalue)·고유벡터(eigenvector): 공분산 행렬 $\Sigma$에 대해 $\Sigma v = \lambda v$를 만족하는 벡터 $v$(고유벡터, 방향)와 스칼라 $\lambda$(고유값, 그 방향으로의 분산 크기). 고유값이 큰 순서로 고유벡터를 정렬한 것이 제1주성분(PC1), 제2주성분(PC2), ...이다.

설명 분산 비율(explained variance ratio): 각 주성분이 전체 분산 중 차지하는 비율.

$$\text{설명 분산 비율}k = \frac{\lambda_k}{\sum{j=1}^{p} \lambda_j}$$

주성분 점수(PC score): 원래 데이터를 주성분 방향에 투영(내적)한 값. $\text{점수} = \tilde{x} \cdot v$

적재값(loading): 고유벡터 $v$의 각 성분 — 원래 변수 하나하나가 그 주성분에 얼마나, 어떤 부호로 기여하는지를 나타낸다.

왜 표준화가 먼저 필요한가: PCA는 분산이 큰 변수를 "더 중요한 변수"로 취급한다. 청구액(수만~수십만 원 단위)과 상환액(단위는 같지만 분포가 다름)처럼 단위·스케일이 다른 변수를 그대로 쓰면 스케일이 큰 변수가 부당하게 주성분을 지배하므로, PCA 전에 반드시 StandardScaler로 표준화한다(2부에서 배운 것과 같은 이유).

5. 손으로 확인하는 작은 숫자 예제

$(2,3), (3,4), (4,5.5), (5,6)$ 4개의 2차원 점으로 PCA를 손으로 계산해보자.

평균: $\bar{x} = (3.5,\ 4.625)$

중심화된 데이터 $\tilde{X}$: $(-1.5,-1.625),\ (-0.5,-0.625),\ (0.5,0.875),\ (1.5,1.375)$

공분산 행렬(각 원소는 $\frac{1}{n-1}\sum \tilde{x}_i \tilde{x}_j$, $n=4$):

$$\Sigma = \begin{pmatrix} 1.667 & 1.750 \ 1.750 & 1.896 \end{pmatrix}$$

이 행렬의 고유값·고유벡터를 계산하면 $\lambda_1 = 3.535,\ \lambda_2 = 0.028$이고, 제1주성분 방향은 $v_1 \approx (0.684,\ 0.730)$이다. 설명 분산 비율은 $3.535/(3.535+0.028) \approx 0.992$ — 즉 이 4개 점의 흩어짐(분산)의 99.2%가 단 하나의 방향(PC1)만으로 설명된다(그림 6-2). 이는 애초에 이 4개 점이 거의 일직선을 이루도록 만들었기 때문이며, 실제 12개 청구·상환 변수는 이렇게 극단적이지는 않다(7절에서 확인).

6. 데이터 정의와 분석 설계

데이터: 2~4부와 동일한 UCI 신용카드 연체 데이터(credit_default, 실제 데이터, 라이선스 CC BY 4.0). 이번 절에서는 그중 청구액 BILL_AMT1~BILL_AMT6, 상환액 PAY_AMT1~PAY_AMT6 총 12개 수치형 변수만 PCA 대상으로 삼는다.

분할: 2~4부와 동일하게 계좌 단위 무작위 80:20 분할(stratify=default)을 그대로 재사용한다.

검증 규칙(핵심): PCA는 데이터의 분산 구조(공분산 행렬)를 그대로 반영하므로, StandardScaler와 마찬가지로 학습 세트에만 fit하고 테스트 세트에는 transform만 적용해야 한다. 테스트 세트를 포함해 PCA를 학습시키면, 테스트 세트의 분산 정보가 주성분 방향 계산에 스며들어 — 이후 그 주성분으로 만든 피처를 사용하는 모델의 테스트 세트 성능이 실제보다 낙관적으로 나오는 데이터 누수가 된다(3부에서 배운 원칙과 동일한 논리).

7. 단계별 실습 코드와 설명

실행 환경: 2~5부와 동일(Python 3.11+/pandas 3.0.2/numpy 2.4.4/scikit-learn 1.8.0/matplotlib 3.10.9, random_state=42). 전체 실행 시간 약 10초.

7.1 데이터 로드 및 상관관계 확인

import numpy as np
import pandas as pd
from sklearn.model_selection import train_test_split

RANDOM_STATE = 42

raw = pd.read_csv("UCI_Credit_Card.csv")
df = raw.drop(columns=["ID"]).rename(
    columns={"PAY_0": "PAY_1", "default.payment.next.month": "default"}
)
df["EDUCATION"] = df["EDUCATION"].replace({0: 4, 5: 4, 6: 4})
df["MARRIAGE"] = df["MARRIAGE"].replace({0: 3})

bill_cols = [f"BILL_AMT{i}" for i in range(1, 7)]
pay_amt_cols = [f"PAY_AMT{i}" for i in range(1, 7)]
pca_cols = bill_cols + pay_amt_cols  # 12개 청구/상환 금액 변수

df_train, df_test = train_test_split(
    df, test_size=0.2, random_state=RANDOM_STATE, stratify=df["default"]
)

corr = df_train[pca_cols].corr()
print(corr.loc[bill_cols, bill_cols].round(2))
print(corr.loc[pay_amt_cols, pay_amt_cols].round(2))

실제 실행 결과: BILL_AMT 6개 변수는 서로 0.80~0.95의 강한 양의 상관관계를 보인다(인접한 달일수록 더 강함 — BILL_AMT1·BILL_AMT2=0.95, BILL_AMT1·BILL_AMT6=0.80). 반면 PAY_AMT 6개 변수는 서로 0.14~0.31로 상관관계가 약하다 — 실제로 갚은 금액은 달마다 상대적으로 독립적으로 변동한다는 뜻이다(그림 6-1).

7.2 표준화 + 전체 12개 주성분 (스크리 플롯)

from sklearn.preprocessing import StandardScaler
from sklearn.decomposition import PCA

scaler = StandardScaler()
X_train_scaled = scaler.fit_transform(df_train[pca_cols])
X_test_scaled = scaler.transform(df_test[pca_cols])   # 테스트는 transform만

pca_full = PCA(n_components=12, random_state=RANDOM_STATE)
pca_full.fit(X_train_scaled)   # 학습 세트에만 fit
explained = pca_full.explained_variance_ratio_
cum_explained = np.cumsum(explained)
print("설명 분산 비율:", explained.round(3))
print("누적 분산 비율:", cum_explained.round(3))

실제 실행 결과: 개별 설명 분산 비율은 [0.483, 0.140, 0.078, 0.073, 0.068, 0.063, 0.059, 0.022, 0.006, 0.003, 0.002, 0.002]이고, 누적 분산 비율은 6개 주성분에서 90.6%를 넘는다(정확히는 5개에서 84.3%, 6개에서 90.6%) — 즉 12개 변수를 6개로 줄여도 원래 정보의 약 91%를 유지할 수 있다(그림 6-3).

7.3 2개 주성분으로 축소 후 시각화

pca_2d = PCA(n_components=2, random_state=RANDOM_STATE)
X_train_pc2 = pca_2d.fit_transform(X_train_scaled)
print(pca_2d.explained_variance_ratio_.round(3), "합계:", pca_2d.explained_variance_ratio_.sum().round(3))

실제 실행 결과: PC1이 48.3%, PC2가 14.0%를 설명해 2개 합계 62.3%다. 산점도(그림 6-4)에서 정상 고객(파란색)과 연체 고객(빨간색)이 PC1·PC2 평면에서 뚜렷하게 갈라지지는 않는다 — 이는 "청구·상환 금액의 전반적 규모"만으로는 연체 여부를 완전히 구분하기 어렵다는 뜻이며, 4부에서 PAY_1(최근 연체 개월수)이 가장 중요한 예측 변수였던 것과 같은 결론이다. 그림에는 PC1이 30 이상인 매우 극단적인 이상치 계좌가 1~2개 보이는데, 이는 청구·상환 금액이 유난히 큰 소수 고객으로, PCA가 분산 기준으로 방향을 잡기 때문에 이런 이상치에 민감하게 반응할 수 있다는 점을 보여주는 사례다(10절에서 다시 설명).

7.4 주성분 적재값(loading) 해석

loadings = pd.DataFrame(
    pca_2d.components_.T, index=pca_cols, columns=["PC1", "PC2"]
)
print(loadings.round(3))

실제 실행 결과: PC1은 BILL_AMT1~BILL_AMT6 모두에 고르게 0.38~0.40의 양의 적재값을 갖는다 — 즉 PC1은 "전반적인 청구액 규모"를 나타내는 축이다. PC2는 PAY_AMT1~PAY_AMT6에 0.26~0.46의 양의 적재값을, BILL_AMT에는 -0.08~-0.18의 약한 음의 적재값을 갖는다 — PC2는 "청구액 대비 상환을 많이 하는가"를 나타내는 축으로 해석할 수 있다(그림 6-5).

7.5 실무 응용: PCA로 압축한 변수로 분류 성능이 유지되는지 확인

from sklearn.compose import ColumnTransformer
from sklearn.pipeline import Pipeline
from sklearn.preprocessing import OneHotEncoder
from sklearn.linear_model import LogisticRegression
from sklearn.metrics import roc_auc_score

other_num_cols = ["LIMIT_BAL", "AGE"] + [f"PAY_{i}" for i in [1, 2, 3, 4, 5, 6]]
cat_cols = ["SEX", "EDUCATION", "MARRIAGE"]
X_train_full = df_train[other_num_cols + cat_cols + pca_cols]
X_test_full = df_test[other_num_cols + cat_cols + pca_cols]
y_train, y_test = df_train["default"], df_test["default"]

def make_preprocess_full():
    return ColumnTransformer([
        ("num", StandardScaler(), other_num_cols + pca_cols),
        ("cat", OneHotEncoder(handle_unknown="ignore"), cat_cols),
    ])

def make_preprocess_pca(n_components):
    return ColumnTransformer([
        ("num", StandardScaler(), other_num_cols),
        ("bill_pay_pca", Pipeline([
            ("scale", StandardScaler()),
            ("pca", PCA(n_components=n_components, random_state=RANDOM_STATE)),
        ]), pca_cols),
        ("cat", OneHotEncoder(handle_unknown="ignore"), cat_cols),
    ])

pipe_full = Pipeline([("preprocess", make_preprocess_full()),
                       ("model", LogisticRegression(max_iter=1000, random_state=RANDOM_STATE))])
pipe_full.fit(X_train_full, y_train)
auc_full = roc_auc_score(y_test, pipe_full.predict_proba(X_test_full)[:, 1])

results_pca_k = {}
for k in [2, 4, 6, 8]:
    pipe_pca = Pipeline([("preprocess", make_preprocess_pca(k)),
                          ("model", LogisticRegression(max_iter=1000, random_state=RANDOM_STATE))])
    pipe_pca.fit(X_train_full, y_train)
    results_pca_k[k] = roc_auc_score(y_test, pipe_pca.predict_proba(X_test_full)[:, 1])

print("원본 12개:", round(auc_full, 4))
for k, v in results_pca_k.items():
    print(f"PCA {k}개:", round(v, 4))

참고: make_preprocess_pca의 PCA는 Pipeline 안에 있으므로, 이 파이프라인이 X_train_full에 fit될 때 PCA도 학습 세트의 청구·상환 열에만 fit되고, 이후 테스트 세트에는 transform만 적용된다 — 6절에서 정한 검증 규칙이 코드 구조로 자동으로 지켜진다.

실제 실행 결과(테스트 세트, 3부와 동일한 로지스틱회귀 기준):

방식 총 피처 개수 테스트 AUC
원본 12개 변수 그대로 29 0.7100
PCA 2개 주성분으로 대체 19 0.7077
PCA 4개 주성분으로 대체 21 0.7073
PCA 6개 주성분으로 대체 23 0.7081
PCA 8개 주성분으로 대체 25 0.7087

12개 변수를 2개로 압축해도 AUC가 0.7100→0.7077로 0.0023포인트만 낮아진다 — 실무적으로는 거의 차이가 없는 수준이다(그림 6-6).

8. 결과 읽는 법과 업무상 의미

차원 축소의 실질적 효과: 12개 청구·상환 변수의 정보 대부분(약 62%)이 단 2개의 새 변수(PC1: 전반적 청구 규모, PC2: 상환 성향)로 요약된다는 것을 확인했다. 스크리 플롯(그림 6-3)이 급격히 꺾이는 지점(2~3번째 주성분 이후 기울기가 완만해짐)은 "이 이상 주성분을 추가해도 얻는 정보가 크지 않다"는 신호로 읽는다.

분류 성능이 거의 유지되는 이유: 7.5절에서 12개 변수를 2개로 줄여도 AUC가 거의 그대로인 것은, 4부에서 이미 확인했듯 이 데이터에서 연체 예측에 가장 중요한 변수는 BILL_AMT나 PAY_AMT가 아니라 PAY_1(최근 연체 개월수)이기 때문이다. 즉 이번 PCA는 "정보를 거의 잃지 않으면서 변수 개수를 줄이는 데는 성공했지만, 애초에 그 정보가 예측 성능에 크게 기여하지 않았다"는 것도 함께 보여준다 — 차원 축소가 항상 성능 향상으로 이어지는 것은 아니라는 중요한 교훈이다.

해석 가능성과의 trade-off: PCA로 만든 PC1·PC2는 "전반적 청구 규모", "상환 성향"처럼 대략적으로는 해석할 수 있지만, BILL_AMT3처럼 "3개월 전 청구액이 얼마다"라는 구체적 의미는 사라진다. 실무에서 "왜 이 고객의 위험도가 높은가"를 설명해야 하는 상황(다음 절 이후 다룰 설명가능성)에서는 원본 변수를 유지하는 것이 더 나을 수 있다.

10. 흔한 오해와 오류

  • 오해 1: "주성분 개수는 많을수록 무조건 좋다." 주성분을 늘릴수록 원본 정보는 더 많이 보존되지만, 차원 축소의 목적(계산 비용 절감, 시각화, 다중공선성 완화)과 반대로 간다. 스크리 플롯에서 누적 설명 분산이 완만해지는 지점을 실무적 기준으로 삼는다.
  • 오해 2: "PCA로 축소한 변수가 원래 변수보다 항상 예측 성능이 좋다." 7.5절에서 확인했듯 이번 사례에서는 오히려 미세하게 낮아졌다(0.7100→0.7077~0.7087). PCA는 "정보 손실을 최소화하며 압축"하는 것이지, 예측에 더 유리한 변수를 만들어내는 것이 아니다 — 목적변수(연체 여부)를 전혀 보지 않고 압축하기 때문이다(비지도 학습).
  • 오류 1: "PCA는 전체 데이터에 한 번에 fit해도 된다, 어차피 목적변수를 안 보니까 괜찮다." 목적변수를 보지 않아도, 테스트 세트의 입력 변수 분산 구조가 학습 과정에 스며들면 데이터 누수다. 6절에서 설명했듯 PCA도 StandardScaler와 동일하게 학습 세트에만 fit해야 한다. 이 절의 7.5 코드는 Pipeline 안에 PCA를 넣어 이 원칙을 구조적으로 보장했다.
  • 오류 2: "이상치가 있어도 PCA 결과는 안정적이다." 그림 6-4에서 본 것처럼 극단적으로 큰 값을 가진 소수 계좌가 주성분 방향 자체를 왜곡할 수 있다(PCA는 분산 기반이므로 이상치에 민감). 실무에서는 이상치 제거나 로버스트 스케일링을 함께 검토해야 한다(연습문제 5).

11. 핵심 요약

PCA는 서로 상관된 변수들의 분산 구조를 분석해, 분산이 가장 큰 방향(주성분)부터 순서대로 새로운 축을 만든다. 설명 분산 비율과 스크리 플롯으로 몇 개의 주성분을 남길지 판단하며, 이번 사례에서는 12개 청구·상환 변수를 6개 주성분으로 줄여도 정보의 약 91%를 유지했다. PCA도 표준화와 마찬가지로 학습 세트에만 fit해야 하는 전처리 단계이며, 차원 축소가 항상 예측 성능 향상으로 이어지는 것은 아니라는 점, 그리고 이상치에 민감할 수 있다는 점을 실제 수치로 확인했다.

12. 연습문제

개념 문제
1. PCA가 표준화 없이 원본 스케일 그대로 진행되면 어떤 문제가 생기는지, 이 절의 청구액(수만~수십만 원)과 상환액 단위 차이를 예로 들어 설명하라.
2. "PCA로 축소한 변수의 예측 성능이 원본보다 낮게 나왔다"는 결과가 PCA가 잘못되었다는 뜻은 아닌 이유를 설명하라.

계산 문제
3. 공분산 행렬이 $\begin{pmatrix} 4 & 0 \ 0 & 1 \end{pmatrix}$일 때, 제1주성분의 방향과 설명 분산 비율을 구하라.
4. 이 절의 손 계산 예제에서 제2주성분 방향 $v_2 \approx (-0.730, 0.684)$ 위로 각 점을 투영한 점수를 계산하라(중심화된 데이터: $(-1.5,-1.625), (-0.5,-0.625), (0.5,0.875), (1.5,1.375)$).

실습 문제
5. 7.3절의 산점도에서 확인한 극단적 이상치 계좌를 제거한 뒤 PCA를 다시 수행하고, 설명 분산 비율과 적재값이 어떻게 달라지는지 비교하라.
6. BILL_AMT와 PAY_AMT 대신 원본 12개 변수 전체(2~4부에서 쓴 모든 변수)에 PCA를 적용했을 때 몇 개의 주성분으로 90% 분산을 설명할 수 있는지 확인하라.

연습문제 해설(별도)

  1. 표준화 없이 PCA를 하면, 분산이 절대적으로 큰 변수(예: 청구액, 수만~수십만 원 단위)가 분산이 작은 변수(비율 변수 등)보다 훨씬 큰 영향력을 갖게 되어, 주성분이 사실상 "그 변수 하나"를 반영하는 방향으로 치우친다. 표준화로 모든 변수의 분산을 1로 맞춰야 각 변수가 "상대적인 변동성" 기준으로 공정하게 반영된다.
  2. PCA는 목적변수(연체 여부)를 전혀 보지 않고 입력 변수의 분산 구조만으로 압축하는 비지도 방법이다. 압축 후 성능이 유지되거나 소폭 낮아지는 것은 "정보 손실이 예측에 크게 영향을 주지 않을 만큼 적었다"는 뜻이지, PCA 계산 자체가 틀렸다는 뜻이 아니다.
  3. 이미 대각행렬이므로 고유벡터는 축 그대로다. 고유값은 4와 1이므로 제1주성분 방향은 $(1,0)$(분산이 더 큰 축), 설명 분산 비율은 $4/(4+1)=0.8$이다.
  4. $(-1.5,-1.625)\cdot(-0.730,0.684) = 1.095-1.111 = -0.016$; $(-0.5,-0.625)\cdot(-0.730,0.684)=0.365-0.428=-0.063$; $(0.5,0.875)\cdot(-0.730,0.684)=-0.365+0.599=0.234$; $(1.5,1.375)\cdot(-0.730,0.684)=-1.095+0.941=-0.154$. (참고: 계산 시 반올림된 고유벡터 값을 사용했으므로 소수점 이하 오차가 있을 수 있다.)
  5. (실습형) 이상치를 제거하면 PC1의 설명 분산 비율이 다소 낮아지고(극단값이 만들던 인위적인 분산이 사라지므로) 적재값이 6개 BILL_AMT 변수에 더 고르게 분산될 가능성이 높다.
  6. (실습형) PAY_1~PAY_6처럼 이미 이산적인(정수형) 변수가 섞이면 분산 구조가 달라져, 90% 도달에 필요한 주성분 개수가 이 절의 6개와 달라질 수 있다.
