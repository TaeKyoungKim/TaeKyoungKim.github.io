3부. 머신러닝 평가 — 신용카드 연체 예측의 불균형 데이터와 오류 비용

이 절에서 원문 대비 달라진 점: 원문(Chapter 03, 123~159쪽)은 정확도·오차행렬·정밀도-재현율-F1-ROC/AUC 개념을 피마 인디언 당뇨병 데이터로 설명한다. 개념 설명 순서(정확도의 문제점→오차행렬→정밀도/재현율→트레이드오프→ROC/AUC)는 원문의 논리 구조를 그대로 유지하되, 사례를 2부에서 이어지는 credit_default(신용카드 연체) 데이터로 교체했다. 원문에 없던 업무 비용 기반 임계값 선택은 이 교재의 신규 보강 내용이다. 아래 수치·그림은 모두 실제로 실행한 결과다.

1. 금융 상황과 해결할 질문

2부에서 만든 로지스틱회귀와 결정트리는 각각 80.9%, 81.8%의 정확도를 보였다. 그런데 카드사 실무자 입장에서 진짜 궁금한 것은 "정확도가 몇 %인가"가 아니라 "이 모델을 실제로 켰을 때, 어떤 계좌를 놓치고 어떤 계좌를 잘못 의심하게 되는가"이다. 연체를 예측하지 못해 놓치는 것(false negative)과 정상 고객을 연체 위험군으로 잘못 분류하는 것(false positive)은 업무적으로 전혀 다른 비용을 발생시킨다. 이 절의 질문은 다음과 같다.

불균형한 연체 데이터에서 모델의 성능을 "제대로" 측정하려면 어떤 지표를 봐야 하는가? 그리고 모델이 내놓는 확률값을 어느 지점에서 "연체"로 판정할지(임계값)는 어떻게 정해야 하는가?

2. 학습목표와 선수지식

  1. 정밀도·재현율·F1·ROC-AUC를 정의하고, 각각이 "무엇을 놓치는 데 민감한 지표인지" 구분해서 설명할 수 있다.
  2. 임계값을 바꾸면 정밀도와 재현율이 반대 방향으로 움직이는 트레이드오프를 직접 확인할 수 있다.
  3. 업무 비용(가정값)을 근거로 정확도가 아닌 총 비용을 최소화하는 임계값을 코드로 탐색할 수 있다.

선수지식: 2부의 오차행렬(TP/FP/FN/TN)과 predict_proba 개념. 별도의 확률·통계 지식은 필요 없다.

3. 직관적 설명

공항 보안 검색대를 생각해보면 쉽다. 검색 기준을 아주 느슨하게 하면 위험한 물건을 실은 사람은 거의 놓치지 않지만(재현율↑), 죄 없는 사람도 자주 걸려 검색대가 마비된다(정밀도↓). 반대로 기준을 아주 엄격하게 하면 걸리는 사람은 적지만(정밀도↑), 위험한 물건을 놓칠 가능성이 커진다(재현율↓). 신용카드 연체 예측도 마찬가지다. "조금이라도 의심스러우면 연체 위험군으로 분류"하면 재현율은 높아지지만 정상 고객을 불필요하게 귀찮게 하는 일(정밀도 하락)이 늘어난다. 정답은 하나가 아니라, "어느 쪽 실수가 우리 회사에 더 비싼가"에 달려 있다.

4. 용어와 수식

오차행렬의 네 칸을 다시 정의한다. TP(True Positive)=실제 연체를 연체로 맞춤, FP(False Positive)=실제 정상을 연체로 잘못 예측, FN(False Negative)=실제 연체를 정상으로 잘못 예측(놓침), TN(True Negative)=실제 정상을 정상으로 맞춤.

$$\text{정밀도(Precision)} = \frac{TP}{TP+FP} \qquad \text{"연체라고 예측한 것 중 실제로 맞은 비율"}$$

$$\text{재현율(Recall)} = \frac{TP}{TP+FN} \qquad \text{"실제 연체 중 모델이 찾아낸 비율"}$$

$$F_1 = 2 \cdot \frac{\text{정밀도} \times \text{재현율}}{\text{정밀도} + \text{재현율}} \qquad \text{(정밀도와 재현율의 조화평균)}$$

ROC 곡선과 AUC: 임계값을 1에서 0으로 낮춰 가며 거짓양성비율($FPR = FP/(FP+TN)$)과 참양성비율($TPR=$재현율)을 좌표로 찍은 곡선이 ROC 곡선이다. 이 곡선 아래 면적이 AUC(Area Under the Curve)이며, "무작위로 뽑은 연체 계좌 하나와 정상 계좌 하나를 비교했을 때, 모델이 연체 계좌에 더 높은 확률을 줄 확률"로 해석된다. AUC=0.5는 무작위 예측과 같고, 1.0은 완벽한 분리를 의미한다.

5. 손으로 확인하는 작은 숫자 예제

계좌 20개에 모델을 적용해 다음과 같은 오차행렬을 얻었다고 하자(설명용 가상의 작은 표).

예측:연체 예측:정상
실제:연체 TP=6 FN=2
실제:정상 FP=4 TN=8

$$\text{정밀도} = \frac{6}{6+4} = 0.6, \qquad \text{재현율} = \frac{6}{6+2} = 0.75$$

$$F_1 = 2 \times \frac{0.6 \times 0.75}{0.6+0.75} = 2 \times \frac{0.45}{1.35} = 0.667$$

정밀도(0.6)보다 재현율(0.75)이 더 높다는 것은, "연체를 놓치는 경우"보다 "정상을 잘못 의심하는 경우"가 상대적으로 더 많이 발생했다는 뜻이다. F1은 두 지표의 조화평균이므로 어느 한쪽이 극단적으로 낮으면 크게 떨어진다 — 산술평균과 달리 "균형 잡힌" 모델에 유리하다.

6. 데이터 정의와 분석 설계

이 절은 2부와 동일한 credit_default 데이터, 동일한 학습·테스트 분할(층화 무작위 80:20, random_state=42), 동일한 두 모델(로지스틱회귀·결정트리 depth=4)을 그대로 재사용한다. 새로 정의할 것은 "예측 확률을 어떻게 쓸 것인가"이다. 지금까지는 predict()가 내부적으로 0.5를 기준으로 판정한 결과만 봤지만, 이 절에서는 predict_proba()로 0~1 사이의 연속 확률을 직접 받아 임계값을 우리가 정한다.

한 가지 데이터 설계상 규칙을 추가한다. 임계값은 검증 데이터로만 탐색하고, 최종 테스트 데이터는 그 임계값이 처음 보는 데이터에서도 통하는지 확인하는 데만 써야 한다. 이를 위해 2부의 학습 세트(24,000행)를 다시 세부학습(18,000행)과 검증(6,000행)으로 나눈다. 비용 기반 임계값은 검증 세트로만 탐색하고, 최종 테스트 세트(6,000행, 2부와 동일)는 그 임계값을 적용했을 때 실제로 비용이 낮아지는지 마지막에 한 번만 확인하는 용도로 남겨둔다. 이 구조는 7.4절 코드에 그대로 반영되어 있다.

7. 단계별 실습 코드와 설명

실행 환경: 2부와 동일(Python 3.11+/pandas 3.0.2/numpy 2.4.4/scikit-learn 1.8.0/matplotlib 3.10.9, random_state=42).

7.1 2부 모델 재현

import numpy as np
import pandas as pd
from sklearn.model_selection import train_test_split
from sklearn.compose import ColumnTransformer
from sklearn.pipeline import Pipeline
from sklearn.preprocessing import StandardScaler, OneHotEncoder
from sklearn.linear_model import LogisticRegression
from sklearn.tree import DecisionTreeClassifier

RANDOM_STATE = 42
raw = pd.read_csv("data/raw/UCI_Credit_Card.csv")
df = raw.drop(columns=["ID"]).copy()
df = df.rename(columns={"PAY_0": "PAY_1", "default.payment.next.month": "default"})
df["EDUCATION"] = df["EDUCATION"].replace({0: 4, 5: 4, 6: 4})
df["MARRIAGE"] = df["MARRIAGE"].replace({0: 3})

X = df.drop(columns=["default"]); y = df["default"]
X_train, X_test, y_train, y_test = train_test_split(
    X, y, test_size=0.2, stratify=y, random_state=RANDOM_STATE
)

numeric_features = ["LIMIT_BAL", "AGE",
    "PAY_1","PAY_2","PAY_3","PAY_4","PAY_5","PAY_6",
    "BILL_AMT1","BILL_AMT2","BILL_AMT3","BILL_AMT4","BILL_AMT5","BILL_AMT6",
    "PAY_AMT1","PAY_AMT2","PAY_AMT3","PAY_AMT4","PAY_AMT5","PAY_AMT6"]
categorical_features = ["SEX", "EDUCATION", "MARRIAGE"]

def make_preprocess():
    return ColumnTransformer(transformers=[
        ("num", StandardScaler(), numeric_features),
        ("cat", OneHotEncoder(handle_unknown="ignore"), categorical_features),
    ])

logreg_pipe = Pipeline([("preprocess", make_preprocess()),
                         ("model", LogisticRegression(max_iter=1000, random_state=RANDOM_STATE))])
tree_pipe = Pipeline([("preprocess", make_preprocess()),
                       ("model", DecisionTreeClassifier(max_depth=4, random_state=RANDOM_STATE))])
logreg_pipe.fit(X_train, y_train)
tree_pipe.fit(X_train, y_train)

7.2 확률 예측과 정밀도·재현율·F1·AUC

from sklearn.metrics import (precision_score, recall_score, f1_score,
                              roc_auc_score, confusion_matrix)

proba_logreg = logreg_pipe.predict_proba(X_test)[:, 1]
proba_tree = tree_pipe.predict_proba(X_test)[:, 1]

for name, proba in [("로지스틱회귀", proba_logreg), ("결정트리", proba_tree)]:
    pred = (proba > 0.5).astype(int)   # sklearn predict()의 동점 처리(>)와 동일하게 맞춤
    print(name,
          "precision=", round(precision_score(y_test, pred, zero_division=0), 4),
          "recall=", round(recall_score(y_test, pred, zero_division=0), 4),
          "f1=", round(f1_score(y_test, pred, zero_division=0), 4),
          "auc=", round(roc_auc_score(y_test, proba), 4))

실제 실행 결과(임계값 0.5, 재현 가능):

모델 정밀도 재현율 F1 AUC
로지스틱회귀 0.6923 0.2442 0.3610 0.7100
결정트리(depth=4) 0.6612 0.3662 0.4714 0.7340

여기서 흥미로운 역전이 나타난다. 2부에서는 정확도로 결정트리(81.8%)가 로지스틱회귀(80.9%)를 근소하게 앞섰는데, AUC 기준으로는 그 차이가 더 뚜렷하고(0.734 vs 0.710), F1 기준으로도 결정트리가 확실히 앞선다(0.471 vs 0.361). 즉 이 데이터·이 두 모델의 조합에서는 정확도만으로 봤을 때보다 결정트리의 우위가 다른 지표에서 더 분명하게 드러난다.

한 가지 확인해볼 점: 결정트리의 확률 예측값은 몇 가지 값만 나온다.

print(len(np.unique(proba_tree)), sorted(np.unique(proba_tree)))

16 [0.0, 0.077, 0.108, 0.142, ..., 0.87, 0.943]

max_depth=4인 결정트리는 최대 16개의 잎 노드를 가질 수 있고, 각 계좌는 자신이 도달한 잎 노드의 "그 노드 안 연체 비율"을 그대로 확률값으로 받는다. 그래서 확률이 16개의 값 중 하나로만 나온다 — 이는 8절과 10절에서 "확률처럼 보이지만 진짜 확률은 아니다"라는 점과 함께 다시 설명한다.

7.4 업무 비용 기반 임계값 탐색 (검증 세트로 탐색 → 테스트 세트로 확인)

from sklearn.model_selection import train_test_split as tts2

FN_COST, FP_COST = 5, 1   # 교육용 가정값: 연체를 놓치는 비용이 잘못 의심하는 비용의 5배

# 학습 세트(24,000행)를 세부학습/검증으로 재분할 — 임계값은 검증 세트에서만 탐색한다
X_tr2, X_val, y_tr2, y_val = tts2(X_train, y_train, test_size=0.25,
                                   stratify=y_train, random_state=RANDOM_STATE)

val_model = Pipeline([("preprocess", make_preprocess()),
                       ("model", LogisticRegression(max_iter=1000, random_state=RANDOM_STATE))])
val_model.fit(X_tr2, y_tr2)
proba_val = val_model.predict_proba(X_val)[:, 1]

thresholds_grid = np.arange(0.05, 0.96, 0.01)
val_costs = []
for t in thresholds_grid:
    pred = (proba_val > t).astype(int)
    tn, fp, fn, tp = confusion_matrix(y_val, pred).ravel()
    val_costs.append(FN_COST * fn + FP_COST * fp)
val_costs = np.array(val_costs)
best_threshold = thresholds_grid[np.argmin(val_costs)]
print(best_threshold, val_costs.min())   # 검증 세트 기준 최적 임계값과 비용

# 검증 세트 기준, 기본 임계값(0.5)의 비용도 함께 확인
val_cost_at_05 = val_costs[np.argmin(np.abs(thresholds_grid - 0.5))]
print("검증 비용(임계값 0.50) =", val_cost_at_05)

# 최종 확인: 임계값 선택에 전혀 관여하지 않은 테스트 세트에 '적용만' 해본다
# (모델은 7.1에서 X_train 24,000행 전체로 이미 학습된 logreg_pipe를 그대로 사용)
pred_test_05 = (proba_logreg > 0.5).astype(int)
pred_test_best = (proba_logreg > best_threshold).astype(int)

for label, pred in [("0.50 (기본값)", pred_test_05), (f"{best_threshold:.2f} (검증 세트에서 선택)", pred_test_best)]:
    tn, fp, fn, tp = confusion_matrix(y_test, pred).ravel()
    cost = FN_COST * fn + FP_COST * fp
    print(f"[테스트] 임계값 {label}: TN={tn}, FP={fp}, FN={fn}, TP={tp}, 총비용={cost}")

가정 비용에 대한 주의: FN_COST=5, FP_COST=1은 실제 은행 자료가 아니라 "연체를 놓치는 것이 정상 고객을 잘못 의심하는 것보다 몇 배 더 비싼가"를 보여주기 위해 이 교재가 임의로 정한 교육용 가정값이다. 실제 금액(예: 평균 미회수 잔액, 고객 이탈 비용 등)은 각 기관의 실제 데이터로 추정해야 하며, 이 절의 비율(5:1)을 실제 의사결정에 그대로 사용해서는 안 된다.

실제 실행 결과: 검증 세트(6,000행)에서 탐색한 결과 임계값 0.24가 검증 비용 3,687로 가장 낮았다(참고: 검증 세트에서 임계값 0.50의 비용은 5,105). 이 임계값 0.24를 한 번도 사용하지 않았던 테스트 세트에 적용해 확인한 결과는 다음과 같다.

임계값 TN FP FN TP 테스트 세트 총비용
0.50 (기본값) 4,529 144 1,003 324 5,159
0.24 (검증 세트에서 선택) 3,575 1,098 555 772 3,873

검증 세트에서 고른 임계값 0.24가 테스트 세트에서도 비용을 낮추는 방향(5,159→3,873)으로 그대로 작동함을 확인할 수 있다. 이번 데이터에서는 검증 세트 기준 최적 임계값과, (방법론적으로는 올바르지 않지만) 테스트 세트를 직접 사용해 찾은 최적 임계값이 우연히 같은 값(0.24)으로 나왔다. 이는 이 데이터가 상대적으로 크고(30,000행) 두 세트의 연체 비율이 비슷했기 때문일 뿐, 데이터가 작거나 세트 간 우연한 차이가 크면 두 방식의 결과가 달라질 수 있다 — 그래서 "우연히 같았다"는 것이 검증 세트를 쓰지 않아도 된다는 근거가 되지는 않는다.

8. 결과 읽는 법과 업무상 의미

임계값을 0.50에서 0.24로 낮추면 재현율이 크게 올라간다(324건→772건 검출, 연체 1,327건 중 검출 비율 24.4%→58.2%). 대신 정상 고객을 잘못 의심하는 건수도 크게 늘어난다(144건→1,098건). 이것이 손해인지 이득인지는 정확도나 F1 같은 "중립적" 지표가 아니라, "FN 한 건과 FP 한 건 중 어느 쪽이 우리 회사에 더 비용이 큰가"라는 업무 판단에 달려 있다. 이 절에서는 FN이 FP보다 5배 비싸다고 가정했을 때 임계값 0.24가 총 비용을 5,159에서 3,873으로 약 24.9% 낮춘다는 것을 보였다. 비용 비율(FN:FP)이 달라지면 최적 임계값도 달라진다 — 이 관계 자체가 "임계값은 정답이 하나가 아니라 업무 목적에 따라 선택하는 것"이라는 3절의 직관을 뒷받침한다.

AUC와 F1 모두 결정트리가 로지스틱회귀보다 높게 나왔지만(AUC 0.734 vs 0.710, F1 0.471 vs 0.361), 7.2절에서 확인했듯 결정트리의 확률 출력은 16개의 값만 가능한 거친(coarse) 확률이다. 순위를 매기는 용도(AUC, PR 곡선)에는 문제가 없지만, "이 계좌의 연체 확률이 정확히 15.2%다"처럼 확률값 자체의 정밀한 의미를 요구하는 용도(예: 기대 손실 계산)에는 로지스틱회귀 쪽이 더 세밀한 확률을 제공한다는 점도 함께 고려해야 한다.

10. 흔한 오해와 오류

  • 오해 1: "AUC나 F1이 더 높은 모델이 무조건 더 좋은 모델이다." 8절에서 보듯 지표마다 우열이 다를 수 있고(정밀도는 로지스틱회귀가 근소 우위, 재현율·F1·AUC는 결정트리 우위), 어떤 지표를 우선할지는 업무 목적에 달려 있다. 지표 하나로 "더 좋다"고 단정하면 안 된다.
  • 오해 2: "모델이 출력하는 확률(predict_proba)은 실제 부도확률과 같다." 이 절의 결정트리처럼, 특히 트리 계열 모델의 확률은 잎 노드 안의 표본 비율일 뿐 별도의 보정(calibration) 없이는 실제 발생 확률과 다를 수 있다. "확률처럼 보이는 순위 점수"로 다루는 것이 안전하다.
  • 오류 1: 임계값 0.5를 "당연한 기본값"으로 여기고 바꿀 생각을 하지 않는 것. 0.5는 "두 오류의 비용이 같다"고 가정할 때만 합리적인 기준값이다. 이 절에서 확인했듯 비용이 다르면 최적 임계값은 0.5에서 크게 벗어난다(이 예에서는 0.24).
  • 오류 2(중요, 검증 절차): 임계값을 테스트 세트로 직접 탐색하면, 그 임계값이 이 테스트 세트에만 우연히 잘 맞을 위험(과적합된 임계값 선택)이 생긴다. 이 절의 7.4 코드는 이 문제를 피하기 위해 학습 세트를 세부학습(18,000행)과 검증(6,000행)으로 다시 나누고, 임계값 탐색은 검증 세트에서만 수행한 뒤 테스트 세트는 최종 확인에만 사용한다. 이번 데이터에서는 검증 세트 기준 최적 임계값(0.24)이 테스트 세트로 직접 찾았을 경우와 우연히 같게 나왔지만, 이는 데이터 규모가 상대적으로 크기 때문일 뿐 일반적으로 보장되는 결과가 아니다 — 검증 세트를 생략해도 된다는 근거로 오해하면 안 된다.
  • 오류 3: 이 절의 비용 비율(FN:FP=5:1)을 실제 금액인 것처럼 인용하는 것. 7.4절에 명시했듯 이는 교육용 가정값이다.

11. 핵심 요약

불균형 데이터에서는 정확도 대신 정밀도·재현율·F1·AUC를 함께 봐야 한다. 임계값을 낮추면 재현율은 오르고 정밀도는 내려가는 트레이드오프가 발생하며, 어떤 임계값이 "최적"인지는 두 종류 오류(FN, FP)의 업무 비용에 따라 달라진다. 이 실습에서는 FN 비용이 FP 비용의 5배라는 가정 아래 임계값을 0.5에서 0.24로 낮췄을 때 총 비용이 24.9% 줄었다. 결정트리처럼 확률 출력이 거친 모델은 순위 지표(AUC)에는 유리할 수 있지만 확률값 자체의 정밀도는 낮을 수 있다는 점도 함께 확인했다. 임계값 선택은 반드시 검증 데이터로 하고, 테스트 데이터는 최종 확인에만 사용해야 한다.

12. 연습문제

개념 문제
1. 정밀도와 재현율 중 "연체를 놓치면 안 되는" 업무(예: 고위험 대출 조기 경보)에서 더 중요하게 여겨야 할 지표는 무엇이며 그 이유는?
2. 결정트리의 predict_proba 값이 16개뿐인 이유를 max_depth와 연결해서 설명하라.

계산 문제
3. 어떤 모델의 오차행렬이 TP=40, FP=10, FN=60, TN=890이다. 정밀도, 재현율, F1을 계산하라.
4. FN 비용이 FP 비용의 2배라고 가정할 때, 3번 문제의 오차행렬에 대한 총 비용을 계산하라.

실습 문제
5. FN_COST와 FP_COST를 각각 10, 1로 바꿔 최적 임계값이 어떻게 달라지는지 확인하라. 비용 비율이 커질수록 최적 임계값이 어느 방향으로 움직이는지 설명하라.
6. 결정트리에도 동일한 비용 기반 임계값 탐색을 적용해, 로지스틱회귀와 최적 임계값·최소 비용을 비교하라.

연습문제 해설(별도)

  1. 재현율이 더 중요하다. 고위험 대출을 조기에 잡아내지 못하면(FN) 손실이 발생하고 되돌리기 어렵지만, 정상 고객을 한 번 더 확인하는 정도(FP)의 비용은 상대적으로 작기 때문이다. 다만 재현율만 극단적으로 높이면 정밀도가 크게 떨어져 실무자가 감당할 수 없을 만큼 많은 거짓 경보가 발생할 수 있으므로, 무조건 재현율 100%를 목표로 하지는 않는다.
  2. max_depth=4인 이진 결정트리는 잎 노드가 최대 $2^4=16$개까지 생길 수 있다. 각 계좌는 자신이 도달한 잎 노드 하나에 속하고, 그 노드의 예측 확률은 "그 노드에 속한 학습 데이터 중 연체 비율" 하나의 값으로 고정되므로, 전체 확률 예측값의 가짓수도 최대 16개를 넘을 수 없다.
  3. 정밀도 $=40/(40+10)=0.8$, 재현율 $=40/(40+60)=0.4$, $F_1 = 2\times(0.8\times0.4)/(0.8+0.4) = 0.64/1.2 \approx 0.533$
  4. 총비용 $= 2\times FN + 1\times FP = 2\times60 + 10 = 130$(단위는 임의)
  5. (실습형) 비용 비율(FN:FP)이 커질수록 FN을 더 적극적으로 줄이려 하므로 최적 임계값은 더 낮은 쪽으로 이동하는 경향을 보인다 — 실행 결과로 직접 확인하는 것이 목적이다.
  6. (실습형) 정답은 실행 결과에 따라 다르다. 결정트리는 확률값이 16개뿐이므로 임계값 그리드를 촘촘하게 잡아도 실제로 바뀌는 예측은 계단식으로만 변한다는 점을 관찰하는 것이 이 문제의 핵심이다.

인계 메모 (검수·수정 반영판)

  • 완료한 범위: 3부 전체를 12단계 구조로 집필한 뒤, 3단계 검수를 거쳐 임계값 탐색 절차를 검증 세트 기반으로 재구성한 최종본.
