2부. 전처리와 첫 분류 — 신용카드 연체 예측 모델 만들기

이 절에서 원문 대비 달라진 점: 원문(Chapter 02, 68~122쪽)은 붓꽃(iris) 데이터로 사이킷런 API를 소개한 뒤 타이타닉 생존자 예측을 첫 실전 랩으로 다룬다. 이 절에서는 사이킷런 API 소개는 최소화하고, 원문 6장(351~355쪽)에서 이미 사용된 UCI "Default of Credit Card Clients" 데이터셋(대만, 2005년 4~9월, 30,000개 계좌)을 앞당겨 가져와 이 교재 전체(2~4부, 6부)에서 반복 사용하는 축 데이터로 삼는다. 아래 수치·그림은 모두 이 데이터로 실제로 실행한 결과이며, 원문에서 그대로 가져온 서술은 없다(전부 새로 작성).

1. 금융 상황과 해결할 질문

카드사는 매달 수백만 건의 청구서를 발행한다. 그중 일부 계좌는 다음 청구월에 대금을 제때 갚지 못한다. 카드사가 "이번 달 상환 이력을 보면, 이 계좌가 다음 달에 연체할 가능성이 높은가?"를 사전에 가늠할 수 있다면, 한도 조정이나 상환 안내 같은 조치를 미리 취할 수 있다. 이 절의 질문은 다음과 같다.

계좌의 과거 상환·청구 이력만으로, 다음 청구월의 연체 여부를 예측할 수 있는가? 그리고 그 예측을 "얼마나 믿을 수 있는가"는 어떻게 확인하는가?

두 번째 질문이 핵심이다. 모델을 학습시키는 것 자체는 몇 줄의 코드로 끝나지만, 그 결과를 업무에 쓸 수 있는지 판단하려면 데이터를 어떻게 나누고 무엇을 확인해야 하는지 먼저 정해야 한다.

2. 학습목표와 선수지식

이 절을 마치면 다음을 할 수 있어야 한다.

  1. 분류 문제를 "한 행이 의미하는 대상 · 관측 시점 · 예측 대상 · 레이블 확정 시점"으로 분해해서 정의할 수 있다.
  2. 결측 처리, 범주형 인코딩, 수치형 스케일링을 사이킷런 Pipeline과 ColumnTransformer로 구성해, 학습 데이터에서만 통계를 추정하도록 만들 수 있다.
  3. 아무 정보도 쓰지 않는 기준모델과 실제 모델(로지스틱회귀, 결정트리)의 정확도를 비교하고, 정확도 하나만으로는 판단이 위험한 이유를 데이터로 확인할 수 있다.

선수지식: 파이썬 기초 문법, pandas DataFrame의 인덱싱·필터링. 금융 지식은 필요 없다(연체·청구·상환의 의미는 4절에서 정의한다). 확률의 기초 개념(0~1 사이 값, 비율)만 알면 된다.

3. 직관적 설명

사람도 비슷한 방식으로 판단한다. 최근 몇 달간 카드값을 제때 갚아온 사람과, 최근 두세 달 연속 늦게 갚은 사람이 있다면, 다음 달에도 늦게 갚을 가능성은 후자가 더 높다고 짐작할 수 있다. 머신러닝 모델이 하는 일은 이런 "짐작"을, 사람이 아니라 수천 개 계좌의 과거 기록에서 통계적인 규칙으로 뽑아내는 것이다. 다만 사람의 직관과 다른 점은, 모델은 "왜"를 이해하지 못한 채 숫자 패턴만 본다는 것이다. 그래서 어떤 숫자(피처)를 넣을지, 그 숫자가 언제 시점의 정보인지를 사람이 먼저 엄격하게 정해줘야 한다.

4. 용어와 수식

연체(default): 이 데이터에서는 "다음 청구월에 최소 결제금액을 기한 내에 납부하지 못한 상태"를 의미하는 이진값(0=정상, 1=연체)이다. 실제 채무불이행(default)의 법적·회계적 정의는 기관마다 다를 수 있으므로, 이 교재에서는 데이터에 기록된 정의를 벗어나 "부도확률(PD)"이나 "12개월 연체율" 같은 다른 개념으로 확장하지 않는다.

청구금액(BILL_AMT): 특정 월의 카드 명세서에 찍힌 청구 총액(신대만달러, NT$).
상환금액(PAY_AMT): 특정 월에 실제로 납부한 금액(NT$).
상환상태(PAY_1~PAY_6): 정수 코드. -1=제때 납부, 1=1개월 연체, 2=2개월 연체, …, 9=9개월 이상 연체.

로지스틱 회귀의 시그모이드 함수: 입력 $x$에 대해 선형결합 $z = w_0 + w_1 x_1 + \cdots + w_p x_p$를 구한 뒤, 이를 0~1 사이의 확률로 바꾸는 함수다.

$$P(y=1\mid x) = \sigma(z) = \frac{1}{1+e^{-z}}$$

지니 계수(Gini impurity): 결정트리가 어떤 기준으로 데이터를 나눌지 정할 때 쓰는 불순도 지표. 노드에 속한 데이터가 클래스 $k$에 속할 비율을 $p_k$라 하면,

$$Gini = 1 - \sum_k p_k^2$$

값이 0이면 노드 안의 모든 데이터가 한 클래스로만 이루어진 상태(완전히 순수함)이고, 두 클래스가 반반이면 0.5로 가장 불순한 상태다.

5. 손으로 확인하는 작은 숫자 예제

실제 데이터에서 계좌 5개만 뽑아 상환상태(PAY_1)와 레이블(default)만 남기면 다음과 같다(단순화를 위해 컬럼 일부만 표시).

계좌 LIMIT_BAL PAY_1 BILL_AMT1 PAY_AMT1 default
A 20,000 2 (2개월 연체) 3,913 0 1
B 120,000 -1 (제때 납부) 2,682 0 1
C 90,000 0 (해당월 청구 없음/정상) 29,239 1,518 0
D 200,000 0 11,073 2,306 0
E 130,000 0 38,358 3,000 0

지니 계수 손 계산: 5개 중 연체(1)가 2개, 정상(0)이 3개이므로 분할 전 지니 계수는

$$Gini_{부모} = 1 - (2/5)^2 - (3/5)^2 = 1 - 0.16 - 0.36 = 0.48$$

"PAY_1 ≥ 1(한 달이라도 연체 이력 있음)"을 기준으로 나누면, 왼쪽 자식(PAY_1≥1)에는 계좌 A만 남고({1}, 순수하므로 Gini=0), 오른쪽 자식(PAY_1<1)에는 B, C, D, E가 남는다(레이블 {1,0,0,0}이므로 $Gini = 1-(1/4)^2-(3/4)^2 = 0.375$). 두 자식의 가중 평균은

$$Gini_{분할후} = \frac{1}{5}(0) + \frac{4}{5}(0.375) = 0.3$$

분할 전(0.48)보다 분할 후(0.3)가 더 순수해졌으므로(불순도 감소 0.18), 결정트리는 이 분할을 채택할 만하다고 판단한다. 뒤에서 실제로 30,000개 전체 데이터로 학습한 결정트리도 PAY_1을 가장 먼저, 가장 중요하게 사용한다는 것을 7절에서 확인한다.

시그모이드 계산 예시(설명용 가상 가중치): 아래 가중치는 실제 학습된 모델의 계수가 아니라 시그모이드 함수의 동작을 보여주기 위한 예시일 뿐이다. $z = -1.5 + 0.8 \times \text{PAY_1}$이라고 가정하면,

  • PAY_1 = 2(2개월 연체)일 때: $z = -1.5 + 1.6 = 0.1$, $\sigma(0.1) = 0.525$ → 연체 확률 약 52.5%
  • PAY_1 = -1(제때 납부)일 때: $z = -1.5 - 0.8 = -2.3$, $\sigma(-2.3) = 0.091$ → 연체 확률 약 9.1%

상환상태가 나쁠수록(PAY_1 값이 클수록) 예측 확률이 높아지는 방향을 확인할 수 있다. 실제 학습된 모델에서도 이와 같은 방향(PAY_1이 클수록 연체 확률 증가)이 나오는지 8절에서 확인한다.

6. 데이터 정의와 분석 설계

검증 규칙(5절)에서 요구하는 6가지 항목을 이 데이터에 맞춰 명시한다.

  1. 한 행이 의미하는 대상: 대만의 개별 신용카드 계좌 1개(총 30,000개, 중복 계좌 없음).
  2. 예측 기준 시점: 2005년 9월(원 데이터의 가장 마지막 청구월) 시점의 계좌 스냅샷.
  3. 피처의 관측 기간: 2005년 4월~9월(6개월)의 상환상태(PAY_1~6), 청구금액(BILL_AMT1~6), 납부금액(PAY_AMT1~6). 모두 예측 기준 시점 이전 또는 그 시점까지의 정보다.
  4. 예측 대상과 미래 예측 기간: "다음 청구월"의 연체 여부. 원 데이터 설명에 정확한 익월 날짜가 별도로 명시되어 있지 않으므로, 이 교재에서는 "관측 시점 t 기준 익월 연체 여부"로만 서술하고 임의로 날짜를 지어내지 않는다.
  5. 레이블이 최종 확정되는 시점: 다음 청구월의 결제 마감일 이후.
  6. 학습·검증·최종 테스트 분할 방법과 이유: 이 데이터는 날짜별로 계좌가 반복 등장하는 패널 데이터가 아니라, 계좌당 한 행만 있는 단면(cross-sectional) 데이터다(ID 컬럼이 1~30,000까지 중복 없이 유일함을 확인함). 따라서 시간 순서를 인위적으로 만들어 시계열 분할을 하지 않고, 레이블 비율을 유지하는 층화 무작위 분할(stratified random split, 80:20)을 사용한다. 이 방식의 한계는 두 가지다. 첫째, "새로 발급된 계좌"에 모델을 적용했을 때의 성능까지는 검증하지 못한다. 둘째, 데이터에 계좌 ID만 있고 별도의 고객 ID가 없어 동일 고객이 여러 계좌를 보유하는 경우까지는 이 데이터로 확인할 수 없다 — 계좌 수준에서는 중복이 없다는 것만 확인된 사실이며, 고객 수준의 독립성은 가정일 뿐임을 밝혀둔다. 두 한계 모두 10절에서 다시 짚는다.

공용 표기: 이 데이터셋은 교재 전체에서 별칭 credit_default로 지칭한다(1단계 설계 문서 5절). 아래 코드에서는 지면상 편의를 위해 변수명을 df로 쓰지만, 이는 credit_default를 가리키는 동일한 데이터다.

7. 단계별 실습 코드와 설명

실행 환경: Python 3.11 이상, pandas 3.0.2, numpy 2.4.4, scikit-learn 1.8.0, matplotlib 3.10.9(모두 이번 실행 환경에서 실제 확인한 버전). 랜덤시드는 42로 고정한다. 데이터 파일은 data/raw/UCI_Credit_Card.csv(30,000행 × 25열, 원본 그대로)에 있다고 가정한다.

7.1 데이터 로드와 컬럼 정리

import numpy as np
import pandas as pd

RANDOM_STATE = 42
raw = pd.read_csv("data/raw/UCI_Credit_Card.csv")
print(raw.shape)   # (30000, 25)

df = raw.drop(columns=["ID"]).copy()
df = df.rename(columns={
    "PAY_0": "PAY_1",                                   # 표기 일관성: PAY_1~PAY_6
    "default.payment.next.month": "default",            # 레이블명 축약
})
print(df.isnull().sum().sum())   # 0 (결측 없음)

실행 결과, 결측치는 0건이다. 다만 컬럼 자체의 코드북 밖 값이 있는지 확인해야 한다.

print(df["EDUCATION"].value_counts().sort_index())
print(df["MARRIAGE"].value_counts().sort_index())

EDUCATION   0:14   1:10585   2:14030   3:4917   4:123   5:280   6:51
MARRIAGE    0:54   1:13659   2:15964   3:323

데이터 사전(4절)에는 EDUCATION이 1~4(대학원/대학/고교/기타), MARRIAGE가 1~3(기혼/미혼/기타)까지만 정의되어 있는데, 실제 데이터에는 EDUCATION=0,5,6과 MARRIAGE=0이라는 정의되지 않은 값이 섞여 있다. 이는 실제 데이터에서 흔히 발생하는 "코드북과 실제 값의 불일치" 사례다. 값을 임의로 삭제하지 않고, 코드북의 "기타" 범주로 명시적으로 합쳐 정보를 보존한다.

df["EDUCATION"] = df["EDUCATION"].replace({0: 4, 5: 4, 6: 4})   # 4 = 기타
df["MARRIAGE"] = df["MARRIAGE"].replace({0: 3})                  # 3 = 기타

print(df["default"].value_counts())
# 0    23364   (77.9%)
# 1     6636   (22.1%)

레이블은 22.1%만 연체(1)인 불균형 데이터다. 이 사실은 5절(다음 절)에서 평가지표를 고를 때 결정적으로 중요해진다.

7.2 학습·테스트 분할

from sklearn.model_selection import train_test_split

X = df.drop(columns=["default"])
y = df["default"]

X_train, X_test, y_train, y_test = train_test_split(
    X, y, test_size=0.2, stratify=y, random_state=RANDOM_STATE
)
print(X_train.shape, X_test.shape)          # (24000, 23) (6000, 23)
print(y_train.mean(), y_test.mean())        # 0.221 0.221 (비율 유지 확인)

stratify=y를 지정했기 때문에 학습·테스트 세트 모두 연체 비율이 22.1%로 동일하게 유지된다. 이는 6절에서 정한 "단면 데이터 + 층화 무작위 분할" 설계를 그대로 코드로 옮긴 것이다.

    # Pipeline이 공유하면, 지금은 두 모델이 같은 X_train으로 학습되어 우연히
    # 문제가 드러나지 않지만, 이후 다른 학습 데이터로 재사용될 경우 서로의
    # 학습된 상태(평균·분산·범주 목록)를 덮어쓸 수 있어 위험하다.
    return ColumnTransformer(transformers=[
        ("num", StandardScaler(), numeric_features),
        ("cat", OneHotEncoder(handle_unknown="ignore"), categorical_features),
    ])

StandardScaler와 OneHotEncoder를 ColumnTransformer로 묶고, 이를 다시 Pipeline에 넣는 이유는 단순히 코드를 짧게 쓰기 위해서가 아니다. Pipeline 안에 있으면 fit()을 호출할 때마다 학습 데이터에서만 평균·분산이나 범주 목록을 추정하고, 테스트 데이터에는 그 결과를 적용만 하게 된다. 만약 전체 데이터에 대해 미리 스케일링을 해버리면, 테스트 데이터의 정보가 학습 과정에 새어 들어가는 누수가 생긴다. 다만 이 데이터는 계좌 중복이나 시간 순서 문제가 없으므로, Pipeline만으로 검증이 완전해진다는 뜻은 아니다 — 시간·고객 중복이 있는 데이터라면 Pipeline 밖에서 분할 방식 자체를 별도로 설계해야 한다(6절 참고).

baseline = DummyClassifier(strategy="most_frequent", random_state=RANDOM_STATE)

logreg_pipe = Pipeline([
    ("preprocess", make_preprocess()),
    ("model", LogisticRegression(max_iter=1000, random_state=RANDOM_STATE)),
])

tree_pipe = Pipeline([
    ("preprocess", make_preprocess()),
    ("model", DecisionTreeClassifier(max_depth=4, random_state=RANDOM_STATE)),
])

결정트리의 max_depth=4는 임의로 정한 것이 아니라 "사람이 읽고 설명할 수 있는 깊이"로 일부러 제한한 것이다. 트리 깊이와 과대적합의 관계는 4부(트리와 앙상블)에서 자세히 다룬다.

8. 결과 읽는 법과 업무상 의미

가장 먼저 눈에 띄는 것은 아무 학습도 하지 않고 항상 "정상"만 찍는 기준모델도 정확도가 77.9%라는 사실이다. 연체 비율이 22.1%뿐이기 때문에, "다 정상이라고 찍기만 해도" 5번 중 4번 가까이는 맞아버린다. 로지스틱회귀(80.9%)와 결정트리(81.8%)가 기준모델보다 나아 보이지만, 오차행렬과 재현율을 보면 그림이 달라진다. 기준모델은 실제 연체 계좌 1,327건을 단 한 건도(재현율 0.0000) 잡아내지 못한다. 로지스틱회귀는 1,327건 중 324건(재현율 0.2442), 결정트리는 486건(재현율 0.3662)을 잡아낸다. 반면 정밀도는 로지스틱회귀가 0.6923으로 결정트리(0.6612)보다 오히려 높다 — "연체라고 예측했을 때 실제로 맞을 확률"은 로지스틱회귀가 근소하게 낫지만, "실제 연체를 놓치지 않는 정도"는 결정트리가 더 낫다는 뜻이다. 이처럼 정밀도와 재현율이 모델마다 다른 방향으로 움직일 수 있다는 것 자체가, 정확도 하나만으로는 두 모델의 우열을 판단할 수 없는 이유다. 두 지표의 트레이드오프와 임계값 조정은 3부에서 본격적으로 다룬다 — 이 절은 "정확도만 보면 안 되는 이유"를 데이터로 예고하는 데서 마무리한다.

두 모델이 어떤 변수를 근거로 판단했는지도 7.5절의 코드로 직접 확인할 수 있다. 로지스틱회귀 계수를 절댓값 기준으로 정렬하면 PAY_1(직전월 상환상태)의 계수가 +0.660으로, 부호가 양수라는 것은 "PAY_1 값이 클수록(연체 개월 수가 많을수록) 연체 확률 예측값이 높아진다"는 뜻이며, 이는 5절의 손 계산 예제·시그모이드 예시와 방향이 일치한다. 결정트리의 피처 중요도에서도 PAY_1이 전체 중요도의 71.7%를 차지해 압도적 1위였고, 그다음이 PAY_2(14.5%)였다. 두 모델이 서로 다른 알고리즘인데도 "가장 최근 상환상태가 가장 강한 신호"라는 같은 결론에 도달했다는 점은 이 신호가 우연이 아닐 가능성을 뒷받침한다. 다만 이것이 인과관계를 의미하지는 않는다. "상환을 늦게 했기 때문에 다음 달에도 연체한다"는 인과적 주장이 아니라, "상환 이력과 다음 달 연체 사이에 강한 상관 패턴이 있다"는 관측일 뿐이다.

로지스틱회귀에서 절댓값이 가장 큰 계수는 사실 EDUCATION_4(기타 학력, -0.970)다. 그러나 이 범주는 전체 30,000건 중 468건(원래 코드북 밖 값이던 0·5·6을 합친 값)밖에 되지 않는 소수 집단이어서, 계수의 절댓값이 크다고 그 효과가 "가장 강하고 신뢰할 만하다"고 해석하면 안 된다. 이는 10절의 오류 2에서 다시 짚는다.

10. 흔한 오해와 오류

  • 오해 1: "정확도가 높으면 좋은 모델이다." 위에서 확인했듯 기준모델도 77.9%가 나온다. 불균형 데이터에서는 정확도 단독으로 모델을 선택하면 안 된다(3부에서 대안 지표를 다룬다).
  • 오해 2: "레이블 인코딩된 정수 컬럼(SEX, EDUCATION, MARRIAGE)은 그냥 숫자니까 숫자형으로 넣어도 된다." SEX=1/2, EDUCATION=1~4처럼 순서가 없는 범주를 숫자 그대로 넣으면 모델이 "2가 1보다 크다"는 잘못된 순서 관계를 학습할 위험이 있다. 이 절에서는 원-핫 인코딩으로 이를 피했다.
  • 오류 1: 표준화(StandardScaler)를 분포를 정규분포로 바꾸는 도구로 오해하는 것. (원문 106쪽에 있었던 서술과 같은 오류다.) StandardScaler는 평균을 0, 분산을 1로 맞출 뿐 분포의 모양(치우침, 꼬리 두께 등)은 그대로 유지한다. 원래 한쪽으로 치우친 분포는 표준화 후에도 치우쳐 있다.
  • 오류 2: EDUCATION=4처럼 표본이 적은 범주(전체 30,000건 중 468건)의 회귀계수가 크게 나왔다고 해서 그 범주의 효과가 강하다고 단정하는 것. 표본이 적은 범주의 계수는 추정이 불안정할 수 있으므로, 이런 계수는 표본 크기와 함께 해석해야 한다.
  • 오류 3: 이 절의 층화 무작위 분할 방식을 다른 금융 데이터(예: 같은 고객이 여러 시점에 반복 등장하는 거래 데이터)에도 그대로 적용하는 것. 이 데이터는 계좌당 한 행뿐이라 무작위 분할이 적절하지만, 고객이 반복 등장하는 데이터에서는 같은 고객이 학습과 테스트 세트에 동시에 나뉘어 들어가는 것 자체가 정보 누수가 될 수 있다(8부에서 다룬다).

11. 핵심 요약

분류 문제는 모델을 고르기 전에 관측 단위·관측 시점·예측 대상·레이블 확정 시점을 먼저 정의해야 한다. 이 데이터는 계좌 단위 단면 데이터이므로 층화 무작위 분할이 적절하다. 전처리(스케일링, 인코딩)는 Pipeline 안에서 학습 데이터로만 추정해야 데이터 누수를 막을 수 있다. 이 데이터는 연체 비율이 22.1%인 불균형 데이터라서 정확도만으로 모델을 비교하면 오도된 결론에 이를 수 있으며, 로지스틱회귀와 결정트리 모두 "가장 최근 상환상태(PAY_1)"를 가장 중요한 신호로 사용했다.

12. 연습문제

개념 문제
1. 이 데이터셋에서 "관측 시점"과 "레이블 확정 시점"이 각각 무엇을 의미하는지 자신의 언어로 설명하라.
2. StandardScaler를 전체 데이터(학습+테스트)에 대해 미리 적용한 뒤 분할하면 어떤 문제가 생기는지 설명하라.

계산 문제
3. 어떤 노드에 정상 7건, 연체 3건이 있다. 이 노드의 지니 계수를 계산하라.
4. 로지스틱 회귀에서 $z = -1.0 + 0.5 \times \text{PAY_1}$이라고 할 때, PAY_1 = 3인 계좌의 예측 확률 $\sigma(z)$를 계산하라(소수점 셋째 자리까지).

실습 문제
5. max_depth를 4가 아니라 2와 8로 바꿔 결정트리를 다시 학습시키고, 테스트 세트 정확도와 오차행렬이 어떻게 달라지는지 비교하라.
6. categorical_features에서 AGE를 10살 단위 구간(예: 20대, 30대…)으로 나눈 범주형 변수를 새로 만들어 추가했을 때 로지스틱회귀 성능이 달라지는지 확인하라.

연습문제 해설(별도)

  1. 관측 시점은 "모델이 예측을 수행하는 시점"으로, 이 데이터에서는 2005년 9월 시점의 계좌 스냅샷이다. 레이블 확정 시점은 "실제로 연체 여부를 알 수 있게 되는 시점"으로, 다음 청구월의 결제 마감일 이후다. 두 시점을 구분하지 않으면, 아직 결정되지 않은 미래 정보를 실수로 피처에 넣는 데이터 누수가 생길 수 있다.
  2. 테스트 데이터의 평균·표준편차 정보가 스케일링 과정에 섞여 들어가, 모델이 간접적으로 테스트 데이터의 분포를 미리 알게 되는 낙관적 편향(정보 누수)이 생긴다. 이렇게 측정한 성능은 실제 운영 환경에서 재현되지 않을 수 있다.
  3. $Gini = 1 - (7/10)^2 - (3/10)^2 = 1 - 0.49 - 0.09 = 0.42$
  4. $z = -1.0 + 0.5\times3 = 0.5$, $\sigma(0.5) = 1/(1+e^{-0.5}) \approx 0.622$
  5. (실습형: 정답은 실행 결과에 따라 다르다.) max_depth=2는 더 단순해져 정확도는 다소 낮아지지만 해석은 쉬워지고, max_depth=8은 학습 데이터에 더 정교하게 맞춰지면서 테스트 세트 성능이 오히려 정체되거나 나빠질 수 있다(과대적합 가능성 — 4부에서 정식으로 다룬다).
  6. (실습형) AGE를 구간화하면 정보 손실이 발생할 수도, 비선형 관계를 로지스틱회귀가 더 잘 잡아낼 수도 있다 — 두 결과를 비교해 어느 쪽이 더 나은지 스스로 판단해보는 것이 이 문제의 목적이다.
