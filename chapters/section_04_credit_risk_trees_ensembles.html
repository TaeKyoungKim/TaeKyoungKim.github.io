4부. 트리와 앙상블 기반 신용위험 모델 비교

이 절에서 원문 대비 달라진 점: 원문(Chapter 04, 160~228쪽)은 결정트리·앙상블(보팅/배깅-랜덤포레스트/부스팅-AdaBoost·GBM)·SVM·kNN 개념을 사용자행동인식 센서데이터, 위스콘신 유방암 데이터, 붓꽃 데이터로 설명한다. 이 절은 결정트리·앙상블 이론 구조는 그대로 유지하되, 사례를 전부 credit_default(신용카드 연체) 데이터로 교체했다. SVM·kNN은 이 데이터 규모(30,000행, 23피처)에서 트리 계열만큼 실무적으로 흔히 쓰이지 않으므로 이 절에서는 다루지 않고, 원문에 없던 GridSearchCV 기반 하이퍼파라미터 탐색(학습 세트 내부 교차검증만 사용) 과 모델 간 피처 중요도 비교를 신규로 보강했다. 아래 수치·그림은 모두 실제로 실행한 결과다.

1. 금융 상황과 해결할 질문

2~3부에서 만든 결정트리(depth=4)는 AUC 0.734, F1 0.471 정도의 성능을 보였다. 신용위험 관리팀이 실제로 모델을 도입한다면 다음 질문에 답해야 한다. "트리를 더 깊게 만들면 성능이 계속 좋아지는가, 아니면 어느 지점부터는 오히려 나빠지는가?" 그리고 "여러 개의 트리를 결합한 앙상블 모델을 쓰면 단일 트리보다 확실히 나아지는가, 그 대가로 무엇을 잃는가?"

결정트리의 깊이를 어떻게 정해야 하며, 랜덤포레스트·GBM 같은 앙상블 모델은 단일 트리보다 얼마나, 어떤 방식으로 더 나은가? 그리고 여러 모델이 "같은 근거"로 판단하고 있다고 믿을 수 있는가?

2. 학습목표와 선수지식

  1. 결정트리의 깊이(max_depth)가 늘어날수록 학습 성능과 테스트 성능이 어떻게 벌어지는지(과적합) 직접 확인하고, 하이퍼파라미터는 테스트 세트가 아니라 교차검증으로 골라야 하는 이유를 설명할 수 있다.
  2. 배깅(랜덤포레스트)과 부스팅(GBM)의 기본 아이디어 차이를 설명하고, 두 앙상블이 단일 트리보다 나은 이유를 직관적으로 설명할 수 있다.
  3. 서로 다른 모델의 피처 중요도를 비교해, 공통된 신호와 모델별 차이를 구분할 수 있다.

선수지식: 2부의 결정트리·지니 계수, 3부의 AUC·F1. GridSearchCV는 원문 2장(94~99쪽)에서 이미 소개된 도구를 그대로 사용한다.

3. 직관적 설명

결정트리 하나에게 신용위험 판단을 맡기는 것은 애널리스트 한 명에게 모든 판단을 맡기는 것과 비슷하다. 트리가 너무 얕으면(경험이 적으면) 뻔한 패턴만 잡아내고, 너무 깊으면(사소한 것까지 다 외우면) 학습 데이터의 우연한 특이사항까지 규칙으로 착각한다(과적합). 랜덤포레스트는 서로 다른 데이터 표본과 서로 다른 피처 부분집합을 본 여러 애널리스트(트리)의 의견을 평균 내는 방식이다. 한 사람의 실수는 다른 사람들의 의견에 희석된다. GBM(그레이디언트 부스팅)은 다른 전략을 쓴다 — 첫 번째 애널리스트가 놓친 사례들을 두 번째 애널리스트가 집중적으로 다시 보고, 그다음 애널리스트가 또 남은 실수를 보완하는 식으로, 순차적으로 실수를 줄여나간다.

4. 용어와 수식

배깅(Bagging, Bootstrap Aggregating): 원본 학습 데이터에서 중복을 허용해 무작위로 다시 뽑은(부트스트랩) 여러 표본으로 각각 트리를 학습시키고, 그 예측을 평균(회귀) 또는 다수결/확률평균(분류)으로 결합하는 방법. 랜덤포레스트는 배깅에 "각 분할마다 일부 피처만 무작위로 고려한다"는 규칙을 추가한 것이다.

부스팅(Boosting): 이전 모델이 틀린 부분에 가중치를 더 주거나(AdaBoost), 이전 모델의 잔차(오차)를 다음 모델이 예측하도록 순차적으로 모델을 추가하는 방법(GBM). 트리를 하나씩 순서대로 쌓아 올린다.

앙상블의 피처 중요도: 개별 트리의 중요도(2부에서 정의한 지니 기반 중요도)를 앙상블에 속한 모든 트리에 대해 평균한 값이다. 트리가 $T$개 있는 앙상블에서 피처 $j$의 중요도는

$$\text{Importance}{\text{ensemble}}(j) = \frac{1}{T} \sum{t=1}^{T} \text{Importance}_{t}(j)$$

소프트 보팅(Soft Voting): 개별 트리가 내놓은 확률값을 평균해 최종 확률로 삼는 방식. 랜덤포레스트의 predict_proba가 바로 이 방식으로 계산된다(각 트리의 하드 예측을 다수결로 세는 "하드 보팅"과는 다르다).

5. 손으로 확인하는 작은 숫자 예제

랜덤포레스트에 트리 5개가 있고, 어떤 계좌 하나에 대해 각 트리가 내놓은 연체 확률이 다음과 같다고 하자.

트리 1 2 3 4 5
예측 확률 0.62 0.55 0.71 0.30 0.48

소프트 보팅(랜덤포레스트가 실제로 하는 방식): 다섯 확률의 평균을 낸다.

$$\bar{p} = \frac{0.62+0.55+0.71+0.30+0.48}{5} = \frac{2.66}{5} = 0.532$$

임계값 0.5를 적용하면 최종 예측은 "연체(1)"이다.

하드 보팅(참고, 다수결): 각 트리의 확률을 0.5 기준으로 미리 0/1로 바꾸면 [1, 1, 1, 0, 0]이 되어 3표 대 2표로 역시 "연체(1)"가 다수결로 뽑힌다. 이 예제에서는 두 방식이 우연히 같은 결론에 도달했지만, 항상 그런 것은 아니다(예: 확률이 [0.51, 0.51, 0.51, 0.0, 0.0]이면 평균은 0.306으로 "정상"이 되지만 하드 보팅은 3표 대 2표로 "연체"가 된다) — 그래서 소프트 보팅과 하드 보팅은 다른 결과를 낼 수 있다.

6. 데이터 정의와 분석 설계

이 절은 2~3부와 동일한 credit_default 데이터, 동일한 학습·테스트 분할을 사용한다. 새로 추가되는 설계 요소는 하이퍼파라미터 탐색 방법이다.

중요한 검증 규칙: 3부에서 임계값을 검증 세트로만 탐색하도록 고쳤던 것과 같은 이유로, 이 절의 결정트리 max_depth, 랜덤포레스트의 n_estimators/max_depth, GBM의 n_estimators/max_depth도 테스트 세트를 들여다보지 않고 학습 세트 내부의 교차검증(GridSearchCV, cv=5 또는 cv=3, scoring="roc_auc")만으로 고른다. 7절의 "결정트리 깊이별 과적합 곡선"(그림 4-1)은 과적합이라는 현상 자체를 눈으로 보여주기 위한 진단용 그림일 뿐, 이 그림에서 "눈으로 보고" 깊이를 고르지 않는다는 점을 분명히 한다 — 실제 깊이 선택은 교차검증 결과(tree_grid.best_params_)로만 결정한다.

7. 단계별 실습 코드와 설명

실행 환경: 2~3부와 동일(Python 3.11+/pandas 3.0.2/numpy 2.4.4/scikit-learn 1.8.0/matplotlib 3.10.9, random_state=42). 전체 실행 시간은 약 2분(GridSearchCV 포함, CPU 기준)이었다.

7.1 데이터 로드 (2~3부와 동일한 절차 — 재현을 위해 최소 형태로 반복)

아래는 2부 7.1~7.2절과 완전히 동일한 절차를 이 절 코드가 그대로 실행되도록 압축한 것이다(설명은 2부를 참고).

import numpy as np
import pandas as pd
from sklearn.model_selection import train_test_split
from sklearn.compose import ColumnTransformer
from sklearn.pipeline import Pipeline
from sklearn.preprocessing import StandardScaler, OneHotEncoder
from sklearn.tree import DecisionTreeClassifier
from sklearn.metrics import roc_auc_score

RANDOM_STATE = 42
raw = pd.read_csv("data/raw/UCI_Credit_Card.csv")
df = raw.drop(columns=["ID"]).copy()
df = df.rename(columns={"PAY_0": "PAY_1", "default.payment.next.month": "default"})
df["EDUCATION"] = df["EDUCATION"].replace({0: 4, 5: 4, 6: 4})
df["MARRIAGE"] = df["MARRIAGE"].replace({0: 3})

X = df.drop(columns=["default"]); y = df["default"]
X_train, X_test, y_train, y_test = train_test_split(
    X, y, test_size=0.2, stratify=y, random_state=RANDOM_STATE
)

numeric_features = ["LIMIT_BAL", "AGE",
    "PAY_1","PAY_2","PAY_3","PAY_4","PAY_5","PAY_6",
    "BILL_AMT1","BILL_AMT2","BILL_AMT3","BILL_AMT4","BILL_AMT5","BILL_AMT6",
    "PAY_AMT1","PAY_AMT2","PAY_AMT3","PAY_AMT4","PAY_AMT5","PAY_AMT6"]
categorical_features = ["SEX", "EDUCATION", "MARRIAGE"]

def make_preprocess():
    return ColumnTransformer(transformers=[
        ("num", StandardScaler(), numeric_features),
        ("cat", OneHotEncoder(handle_unknown="ignore"), categorical_features),
    ])

7.2 결정트리 깊이별 과적합 진단 (참고용)

depths = [1, 2, 3, 4, 5, 6, 8, 10, 15, None]
train_aucs, test_aucs = [], []
for d in depths:
    pipe = Pipeline([("preprocess", make_preprocess()),
                      ("model", DecisionTreeClassifier(max_depth=d, random_state=RANDOM_STATE))])
    pipe.fit(X_train, y_train)
    train_aucs.append(roc_auc_score(y_train, pipe.predict_proba(X_train)[:, 1]))
    test_aucs.append(roc_auc_score(y_test, pipe.predict_proba(X_test)[:, 1]))

for d, tr, te in zip(depths, train_aucs, test_aucs):
    print(d, round(tr, 4), round(te, 4))

실제 실행 결과:

max_depth 1 2 3 4 5 6 8 10 15 제한없음
학습 AUC 0.644 0.694 0.734 0.749 0.766 0.776 0.795 0.823 0.914 1.000
테스트 AUC 0.644 0.690 0.729 0.734 0.742 0.745 0.744 0.724 0.655 0.607

학습 AUC는 깊이가 커질수록 계속 증가해 결국 1.000(완벽한 암기)에 도달하지만, 테스트 AUC는 depth=6 부근에서 정점(0.745)을 찍고 그 이후로는 오히려 떨어진다. 이는 교과서적인 과적합 곡선이다 — 다만 위에서 말했듯 이 곡선은 진단용으로만 쓰고, 실제 깊이 선택은 아래 7.3절의 교차검증으로 한다.

7.3 GridSearchCV로 하이퍼파라미터 탐색 (학습 세트 내부 교차검증만 사용)

from sklearn.model_selection import GridSearchCV
from sklearn.ensemble import RandomForestClassifier, GradientBoostingClassifier

tree_grid = GridSearchCV(
    Pipeline([("preprocess", make_preprocess()), ("model", DecisionTreeClassifier(random_state=RANDOM_STATE))]),
    param_grid={"model__max_depth": [2, 4, 6, 8, 10]}, cv=5, scoring="roc_auc", n_jobs=-1,
)
tree_grid.fit(X_train, y_train)

rf_grid = GridSearchCV(
    Pipeline([("preprocess", make_preprocess()),
              ("model", RandomForestClassifier(random_state=RANDOM_STATE, n_jobs=-1))]),
    param_grid={"model__n_estimators": [100, 300], "model__max_depth": [4, 6, 8]},
    cv=3, scoring="roc_auc", n_jobs=-1,
)
rf_grid.fit(X_train, y_train)

gb_grid = GridSearchCV(
    Pipeline([("preprocess", make_preprocess()),
              ("model", GradientBoostingClassifier(random_state=RANDOM_STATE))]),
    param_grid={"model__n_estimators": [100, 200], "model__max_depth": [2, 3]},
    cv=3, scoring="roc_auc", n_jobs=-1,
)
gb_grid.fit(X_train, y_train)

print("결정트리", tree_grid.best_params_, round(tree_grid.best_score_, 4))
print("랜덤포레스트", rf_grid.best_params_, round(rf_grid.best_score_, 4))
print("GBM", gb_grid.best_params_, round(gb_grid.best_score_, 4))

실제 실행 결과(모두 학습 세트 24,000행 내부 교차검증 기준, 테스트 세트 미사용):

모델 탐색한 하이퍼파라미터 범위 선택된 값 교차검증 AUC

랜덤포레스트 n_estimators ∈ {100,300}, max_depth ∈ {4,6,8} n_estimators=300, max_depth=8 0.7796
GBM n_estimators ∈ {100,200}, max_depth ∈ {2,3} n_estimators=200, max_depth=2 0.7801

교차검증으로 고른 결정트리 깊이(6)가 7.2절 진단 곡선에서 육안으로 확인한 정점(depth=6)과 일치한다 — 이는 교차검증이라는 원칙적인 방법이 실제로도 합리적인 답을 찾아낸다는 것을 보여주는 사례이며, "진단 곡선을 봐도 되고 안 봐도 결과가 같으니 상관없다"는 뜻은 아니다. 데이터나 상황에 따라 두 결과가 달라질 수 있고, 원칙(교차검증)을 따르지 않으면 그 차이를 걸러낼 방법이 없다.

7.4 최종 모델 비교 (테스트 세트로 단 한 번만 확인)

from sklearn.metrics import roc_auc_score, f1_score, precision_score, recall_score

baseline_tree = Pipeline([("preprocess", make_preprocess()),
                           ("model", DecisionTreeClassifier(max_depth=4, random_state=RANDOM_STATE))])
baseline_tree.fit(X_train, y_train)

final_models = {
    "결정트리(2부 기준, depth=4)": baseline_tree,
    "결정트리(GridSearchCV, depth=6)": tree_grid.best_estimator_,
    "랜덤포레스트(GridSearchCV)": rf_grid.best_estimator_,
    "GBM(GridSearchCV)": gb_grid.best_estimator_,
}
for name, model in final_models.items():
    proba = model.predict_proba(X_test)[:, 1]
    pred = (proba > 0.5).astype(int)
    print(name, roc_auc_score(y_test, proba), f1_score(y_test, pred),
          precision_score(y_test, pred), recall_score(y_test, pred))

7.5 피처 중요도 비교

importance_models = {
    "결정트리(depth=6)": tree_grid.best_estimator_,
    "랜덤포레스트": rf_grid.best_estimator_,

for name, model in importance_models.items():
    imp = model.named_steps["model"].feature_importances_
    feature_names = model.named_steps["preprocess"].get_feature_names_out()
    top5 = sorted(zip(feature_names, imp), key=lambda x: -x[1])[:5]
    print(name, [(n.split("__")[-1], round(v, 3)) for n, v in top5])

8. 결과 읽는 법과 업무상 의미

과적합과 하이퍼파라미터 선택: 학습 AUC는 깊이가 커질수록 끝없이 올라가 결국 1.000(모든 학습 데이터를 암기)에 도달하지만, 그것이 "좋은 모델"을 의미하지 않는다는 것을 테스트 AUC가 depth=10 이후 급격히 떨어지는 것으로 확인했다. 교차검증으로 고른 depth=6 트리는 2부의 depth=4 트리보다 AUC가 0.734→0.745로 개선되었다 — 트리 하나만 쓰더라도 깊이를 원칙적인 방법으로 조정하면 성능이 나아질 수 있다는 뜻이다.

앙상블의 효과: 랜덤포레스트(AUC 0.7744)와 GBM(AUC 0.7763)은 단일 결정트리(depth=6, AUC 0.7445)보다 뚜렷하게 나은 AUC를 보인다. 이는 여러 트리를 결합하면 개별 트리의 "우연한 실수"가 평균화되거나(배깅) 순차적으로 보정되는(부스팅) 효과가 실제로 나타난다는 것을 확인해준다.

주의할 점 — AUC와 F1이 다른 방향을 가리킨다: 그런데 F1(임계값 0.5 기준)을 보면 오히려 2부의 단순한 depth=4 트리(0.4714)가 랜덤포레스트(0.4550)나 GBM(0.4645)보다 근소하게 높다. 이것은 모순이 아니다. AUC는 "임계값과 무관하게 확률의 순위를 얼마나 잘 매기는가"를 재고, F1은 "임계값 0.5라는 특정 지점에서" 계산된다. 앙상블 모델의 확률 분포는 단일 트리와 형태가 다를 수 있어서, 같은 0.5라는 임계값이 모델마다 다른 위치에 놓이게 된다. 3부에서 배운 대로, 각 모델에 맞는 최적 임계값을 (검증 세트로) 따로 찾는다면 앙상블의 우위가 F1에서도 드러날 가능성이 높다 — 이는 이 절의 연습문제로 남겨둔다.

피처 중요도의 일치와 차이: 세 모델 모두 PAY_1(가장 최근 상환상태)을 가장 중요한 신호로 꼽았다는 점은 2~3부의 결론과 일관되며, 이 신호가 모델 종류에 의존하지 않는 안정적인 패턴임을 뒷받침한다. 다만 중요도의 "분산" 정도는 모델마다 다르다 — 단일 트리와 GBM은 PAY_1 하나에 중요도가 집중되는 반면(0.648, 0.650), 랜덤포레스트는 PAY_1~PAY_5에 걸쳐 상대적으로 고르게 분산되어 있다(0.287, 0.132, 0.077, 0.071, 0.058). 이는 랜덤포레스트가 각 분할마다 피처의 일부만 무작위로 고려하기 때문에, PAY_1을 쓸 수 없는 분할에서는 PAY_2~5가 대신 선택될 기회를 얻기 때문이다.

10. 흔한 오해와 오류

  • 오해 1: "트리를 깊게 만들수록 항상 더 좋은 모델이 된다." 7.2절에서 확인했듯 학습 성능은 끝없이 좋아 보이지만 테스트 성능은 depth=6 이후 하락한다. 깊이는 "학습 데이터를 얼마나 잘 외웠는가"가 아니라 "새 데이터에서 얼마나 잘 일반화하는가"로 골라야 한다.
  • 오해 2: "AUC가 더 높은 모델은 어떤 임계값에서도 다른 지표까지 다 더 좋다." 8절에서 확인했듯 랜덤포레스트·GBM이 AUC는 더 높지만, 임계값 0.5에서의 F1은 2부의 단순한 트리보다 낮았다. 지표마다, 임계값마다 결론이 달라질 수 있다.
  • 오류 1(중요, 검증 절차): 하이퍼파라미터(트리 깊이, 앙상블 트리 개수 등)를 테스트 세트 성능을 보고 고르면, 3부에서 지적한 것과 같은 종류의 정보 누수가 된다. 이 절은 이를 피하기 위해 GridSearchCV의 교차검증을 학습 세트(24,000행) 내부에서만 수행했고, 테스트 세트는 마지막 비교(7.4절)에만 사용했다.
  • 오류 2: "피처 중요도가 높다는 것은 그 피처가 레이블의 원인이라는 뜻이다." 2부에서도 짚었듯, 중요도는 상관 패턴의 강도를 나타낼 뿐 인과관계를 증명하지 않는다. PAY_1이 중요하다는 것은 "PAY_1과 다음 달 연체 사이에 강한 상관 패턴이 있다"는 뜻이지 "PAY_1을 바꾸면 연체가 바뀐다"는 뜻이 아니다.
  • 오류 3: "여러 모델의 피처 중요도 수치를 그대로 직접 비교해 크기를 비교할 수 있다." 그림 4-3에서 보듯 랜덤포레스트의 최댓값(0.287)은 결정트리·GBM의 최댓값(0.648, 0.650)보다 훨씬 작다. 이는 랜덤포레스트가 "덜 중요해서"가 아니라, 중요도가 여러 피처에 분산되었기 때문이다. 각 모델 안에서의 "상대적 순위"는 비교할 수 있지만, 모델 간 절대값 크기를 직접 비교하는 것은 오해를 부른다.

11. 핵심 요약

결정트리의 깊이는 학습 성능과 테스트 성능이 벌어지는 지점(과적합)을 교차검증으로 찾아야 하며, 테스트 세트로 직접 고르면 안 된다. 랜덤포레스트(배깅)와 GBM(부스팅)은 단일 트리보다 AUC 기준으로 뚜렷이 나은 성능을 보였다(0.745→0.774~0.776). 다만 F1처럼 특정 임계값에 의존하는 지표에서는 이 우위가 그대로 드러나지 않을 수 있으므로, 지표와 임계값을 함께 고려해야 한다. 세 모델 모두 PAY_1을 가장 중요한 신호로 꼽아 일관성을 확인했지만, 중요도가 집중되는 정도는 모델 구조(특히 랜덤포레스트의 무작위 피처 선택)에 따라 달라진다.

12. 연습문제

개념 문제
1. 랜덤포레스트가 배깅에 추가한 "각 분할마다 일부 피처만 무작위로 고려한다"는 규칙이 왜 피처 중요도를 더 고르게 분산시키는지 설명하라.
2. AUC는 개선되었는데 F1(임계값 0.5)은 개선되지 않은 이유를 3부의 임계값 개념과 연결해서 설명하라.

계산 문제
3. 랜덤포레스트 트리 3개가 어떤 계좌에 대해 확률 0.8, 0.3, 0.6을 예측했다. 소프트 보팅으로 최종 확률을 구하고, 임계값 0.5에서 예측 결과(연체/정상)를 밝혀라.
4. 같은 트리 3개의 예측을 하드 보팅(각 트리의 0/1 판정 후 다수결)으로 바꿔 계산하면 결과가 같은지 다른지 확인하라.

실습 문제
5. 랜덤포레스트와 GBM에 대해서도 3부와 같은 방식으로 검증 세트 기반 비용 최적 임계값을 찾아, F1과 총 비용이 2부의 단순 트리보다 실제로 나아지는지 확인하라.
6. GridSearchCV의 param_grid에 더 넓은 범위(예: 랜덤포레스트 max_depth ∈ {4,6,8,10,12})를 추가해 최적값이 그리드 경계에 걸려 있는지(더 넓혀야 하는지) 확인하라.

연습문제 해설(별도)

  1. 배깅만 사용하면 대부분의 트리가 가장 강한 신호(PAY_1)를 최상위 분할에 반복해서 사용해, 앙상블 전체의 중요도가 여전히 PAY_1에 집중될 수 있다. 그러나 각 분할에서 피처의 일부만 무작위로 후보에 올리면, PAY_1이 후보에서 빠진 분할에서는 어쩔 수 없이 PAY_2~5 같은 차순위 피처가 선택되고, 그 결과 여러 트리에 걸쳐 다양한 피처가 골고루 쓰이게 된다.
  2. AUC는 모든 가능한 임계값에서의 성능을 종합한 지표이고, F1은 임계값 0.5라는 한 지점에서만 계산된다. 모델의 확률 분포가 바뀌면 "0.5"라는 고정된 값이 예전과 다른 재현율·정밀도 지점에 해당하게 될 수 있다. 즉 앙상블 모델의 전반적인 순위 능력(AUC)은 좋아졌어도, 하필 0.5라는 임계값에서는 그 개선이 드러나지 않을 수 있다.
  3. 소프트 보팅 평균 $= (0.8+0.3+0.6)/3 = 1.7/3 \approx 0.567$. 임계값 0.5보다 크므로 예측은 "연체".
  4. 하드 보팅: 0.8→1, 0.3→0, 0.6→1이므로 2표 대 1표로 "연체"가 다수결로 나온다. 이 경우 소프트 보팅과 하드 보팅의 결론이 같다(둘 다 "연체").
  5. (실습형) 정답은 실행 결과에 따라 다르다. 랜덤포레스트·GBM은 확률 분포가 다르므로 최적 임계값도 2부의 단순 트리와 다르게 나올 가능성이 높다는 것을 확인하는 것이 목적이다.
  6. (실습형) 그리드 경계값(예: max_depth=8)이 선택되었다면 더 큰 값도 시도해볼 필요가 있다는 신호다. 다만 무작정 범위를 넓히면 계산 시간이 늘어나므로, 성능 개선 폭과 계산 비용을 함께 고려해야 한다.

인계 메모

  • 완료한 범위: 4부("트리와 앙상블 기반 신용위험 모델 비교") 전체를 12단계 구조로 집필하고, 실행·시각 검증까지 완료.
  • 이번 범위의 변수·레이블·예측시점 정의: 2~3부와 완전히 동일(credit_default, 레이블 default, 층화 무작위 80:20 분할, random_state=42). 새로 추가된 것은 하이퍼파라미터(트리 깊이, 앙상블 트리 개수)이며, 전부 학습 세트 내부 교차검증(GridSearchCV, cv=5 또는 3)으로만 탐색했다.
  • 사용 환경과 데이터: 2~3부와 동일(Python 3.11+/pandas 3.0.2/numpy 2.4.4/scikit-learn 1.8.0/matplotlib 3.10.9). 전체 스크립트 실행 시간 약 115초(GridSearchCV 포함, CPU 기준, n_jobs=-1).

  • 남은 문제: (1) AUC는 개선되었으나 F1(임계값 0.5)이 개선되지 않은 현상에 대해, 각 모델별 최적 임계값을 실제로 찾아 F1이 개선되는지는 연습문제로만 남기고 본문에서 직접 실행하지 않음(다음 절 또는 심화 과제) (2) SVM·kNN은 이 절에서 다루지 않기로 설계 단계에서 결정했으며, 원문에 있던 두 알고리즘 개념 설명이 이 교재에서는 생략되었다는 점을 최종 통합 단계(4단계)에서 목차상 문제가 없는지 재확인 필요 — 통합 단계에서 원문 대응표에 정확히 반영 완료(00_integration_appendix.md 참고) (3) AdaBoost는 GBM과 개념적으로 유사해 이 절에서 GBM으로 대표시키고 별도로 다루지 않음 — 원문 대응표에 반영 완료.
