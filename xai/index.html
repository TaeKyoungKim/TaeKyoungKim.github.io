04. SMOTE 심화 특화 가이드 (불균형 데이터 안전 증강)

SMOTE (Synthetic Minority Over-sampling Technique) 핵심 요약
소수 클래스 데이터를 단순 복제(Random Over-sampling)하면 모델이 같은 데이터를 외우는 과적합(Overfitting)이 발생합니다. SMOTE는 가까운 소수 클래스 이웃($k$-NN) 간의 특징 공간 선분 위에서 가상의 합성 표본을 생성합니다.
구분 단순 복제 (Random Over-sampling) SMOTE 합성 보간
생성 원리 기존 소수 클래스 행을 그대로 복사해 중복 추가 기준 소수 표본 $x_i$와 이웃 $x_{nn}$ 사이: $x_{new} = x_i + \lambda(x_{nn} - x_i)$
의사결정 경계 동일 점 주변에만 좁은 결정 영역 생성 소수 클래스 특징 영역을 볼록 결합(Convex)으로 확장
주요 위험 모델 암기 및 심각한 과대적합 이상치(Outlier) 주변 노이즈 확대, 경계선 침범 가능

SMOTE 적용 시 반드시 지켜야 할 3대 안전 규칙

1. 데이터 누수 방지 (가장 중요)
SMOTE는 오직 Train 데이터에만 적용합니다!
Validation이나 Test 세트에 SMOTE를 적용하거나, 전체 데이터에 SMOTE 후 분할하면 미래 정보가 누출되어 평가 결과가 맹목적으로 부풀려집니다. imbalanced-learn의 Pipeline을 써서 각 Cross-Validation Fold 내부에서만 증강되어야 합니다.
2. 시계열 회귀 적용 금지
연속형 매출·수요 예측에는 SMOTE를 쓰지 않습니다!
SMOTE는 이산형 레이블(사기/정상, 이탈/유지)을 전제로 합니다. 시간 순서가 중요한 시계열에서 선형 보간을 수행하면 시간의 불가역성과 계절성 구조가 완전히 파괴됩니다.
3. 범주형 변수 분리 처리
지역 코드(02, 031), 직업 코드 등에 일반 SMOTE의 연속 보간을 적용하면 존재하지 않는 엉뚱한 중간값(예: 025.4)이 생성됩니다. 범주형 특성을 지원하는 SMOTENC를 사용해야 합니다.
4. 평가 지표의 다각화
정확도(Accuracy)는 98% 정상 데이터에서 전부 정상을 찍어도 98%가 나옵니다. 반드시 재현율(Recall), 정밀도(Precision), F1-Score, PR-AUC, ROC-AUC를 함께 평가해야 합니다.

05. 핵심 파이썬 실습 코드

코드 1: 안전한 SMOTE 교차검증 파이프라인 (Data Leakage 차단)

from imblearn.over_sampling import SMOTE
from imblearn.pipeline import Pipeline
from sklearn.model_selection import StratifiedKFold, cross_validate
from sklearn.preprocessing import StandardScaler
from sklearn.linear_model import LogisticRegression

# 1. 안전한 파이프라인 구축 (Fold 내부에서만 Scale -> SMOTE -> Model 순차 실행)
pipeline = Pipeline(steps=[
    ("scale", StandardScaler()),
    ("smote", SMOTE(sampling_strategy=0.50, k_neighbors=5, random_state=42)),
    ("model", LogisticRegression(max_iter=2000, random_state=42)),
])

# 2. 5-Fold 층화 교차검증 실행
cv_scores = cross_validate(
    pipeline, X_train, y_train,
    cv=StratifiedKFold(n_splits=5, shuffle=True, random_state=42),
    scoring={
        "roc_auc": "roc_auc",
        "pr_auc": "average_precision",
        "recall": "recall",
        "precision": "precision"
    },
    return_train_score=False
)

print(f"CV Recall: {cv_scores['test_recall'].mean():.4f}")
print(f"CV PR-AUC: {cv_scores['test_pr_auc'].mean():.4f}")

import shap

explainer = shap.TreeExplainer(model)

07. 실습 중 자주 발생하는 문제 해결표 (FAQ)

Q1. One-Hot Encoding 후 희소 행렬 메모리 오류
OneHotEncoder의 sparse_output=False(또는 구버전 sparse=False)를 사용하면 범주형 카테고리가 많을 때 RAM이 폭주합니다. SHAP 계산 전용 샘플링(200건)을 별도로 만들거나 고유값이 많은 컬럼은 빈도 인코딩으로 대체합니다.
Q2. SHAP 계산 시간이 너무 오래 걸릴 때
전체 테스트 세트(수만 건)를 TreeExplainer에 그대로 넣으면 세션이 멈출 수 있습니다. X_test.sample(200, random_state=42)처럼 대표 표본 200건을 먼저 추출해 해석하는 것이 표준입니다.
Q3. SMOTE 후 테스트 성능이 현실과 너무 다를 때
전체 데이터셋을 분할하기 전에 SMOTE를 실행했는지 확인하세요! 전체 데이터에 SMOTE를 적용하면 테스트 데이터와 흡사한 데이터가 훈련에 들어가 점수가 거짓으로 급등합니다.
Q4. 시계열에서 미래 누수(Leakage)가 의심될 때
shift(1) 또는 lag_7 없이 당일 판매량이나 미래 프로모션 날짜를 그대로 롤링 평균에 넣었는지 점검하세요. 피처 사전의 가용 시점($D$)을 다시 대조합니다.
